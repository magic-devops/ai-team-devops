# 任务模板

## 标准任务模板

```markdown
## Task ID: T{number}

**标题**: [动词 + 对象]
**类型**: code | test | infra | doc | refactor
**优先级**: P0 | P1 | P2 | P3
**估算**: S(<2h) | M(<1d)
**依赖**: [T001, T002] 或 无

---

### 上下文

**相关文件**:
- `src/path/to/file.ts` — [用途说明]

**背景**: [1-2句话说明为什么需要这个任务]

---

### 实现要点

- [ ] 要点1
- [ ] 要点2
- [ ] 要点3

---

### 完成标准 (Done When)

- [ ] 构建通过（`npm run build`）
- [ ] 测试通过（`npm test`）
- [ ] [具体功能验证点1]
- [ ] [具体功能验证点2]

---

### 注意事项

[可选：特殊约束、已知风险、需要避免的做法]
```

---

## 智能体简报模板（Orchestrator → Worker）

```markdown
## 任务简报

**任务**: T{id} — {标题}
**分配给**: {角色}
**上下文预算**: {N}K tokens

### 你需要做什么

{任务描述，2-3句话}

### 需要读取的文件

1. `{文件路径}` — {读取原因}
2. `{文件路径}` — {读取原因}

### 约束条件

- {约束1}
- {约束2}

### 完成后报告

完成后使用以下格式报告：
- 状态：completed / blocked / failed
- 摘要：一句话说明做了什么
- 变更文件：列表
- 解锁任务：列表（如果有）
```

## 问题报告模板

```markdown
## 问题报告 INC-{timestamp}

**标题**: {一句话描述问题}
**严重级别**: P0（生产中断）| P1（功能损坏）| P2（功能降级）| P3（轻微）
**发现时间**: {时间}
**发现者**: {智能体角色 / 用户}

### 问题描述

{详细描述，包括：什么时候发生、什么情况下发生、影响范围}

### 复现步骤

1. {步骤1}
2. {步骤2}
3. 预期结果：{预期}
4. 实际结果：{实际}

### 根因分析

{根因，不是症状}

### 修复方案

{修复方案描述}
关联任务：T{id}

### 预防措施

{如何防止类似问题再次发生}

### 时间线

- {时间} 问题发生
- {时间} 问题发现
- {时间} 开始修复
- {时间} 修复完成
- {时间} 验证通过
```

## Sprint 计划模板

```markdown
## Sprint {N} 计划

**周期**: {开始日期} — {结束日期}
**目标**: {Sprint 目标，一句话}

### 本 Sprint 任务

| ID | 标题 | 估算 | 优先级 | 依赖 |
|----|------|------|--------|------|
| T001 | ... | S | P1 | 无 |
| T002 | ... | M | P1 | T001 |

**总估算**: {X} Story Points
**上个 Sprint 速度**: {Y} Story Points

### 并行执行计划

**第一批（并行）**: T001, T003, T004
**第二批（T001完成后）**: T002, T005
**第三批（全部完成后）**: T006

### 风险

| 任务 | 风险 | 缓解措施 |
|------|------|---------|
| T005 | 依赖外部 SMTP 服务 | 准备 Mailtrap 备用方案 |
```
