# Prompt 模式库

## 模式 1：任务启动 Prompt

```
你是 [角色]，正在处理任务 [T-ID]。

任务：[任务标题]
描述：[任务描述]
完成标准：[Done When]

相关文件：
- [文件路径]（[用途]）

约束：
- [约束1]
- [约束2]

请先读取相关文件，然后实现任务。每完成一个子步骤，运行验证命令确认正确。
```

## 模式 2：代码审查 Prompt

```
你是 Reviewer，审查以下变更。

任务：[T-ID] [任务标题]
Diff：
[git diff 内容]

按照 quality/CODE_REVIEW.md 的清单逐项检查。
输出格式：PASS 或 NEEDS_CHANGES（附具体问题和行号）。
```

## 模式 3：问题诊断 Prompt

```
你是 Debugger，诊断以下问题。

错误信息：
[错误堆栈]

相关代码：
[代码片段]

请：
1. 找到根因（不是症状）
2. 提出最小化修复方案
3. 说明如何验证修复
4. 建议回归测试
```

## 模式 4：上下文恢复 Prompt

```
你正在恢复一个中断的任务。

当前状态（来自记忆系统）：
- 项目阶段：[phase]
- 当前任务：[T-ID] [标题]，状态：[status]
- 已完成步骤：[步骤列表]
- 下一步：[next_step]

相关历史（来自 LanceDB）：
[相似任务/问题摘要]

请从"下一步"继续执行，不要重复已完成的步骤。
```

## 模式 5：需求拆解 Prompt

```
你是 Planner，将以下需求拆解为可执行任务。

需求：[需求描述]

技术栈：[技术栈]
约束：[约束条件]

输出 YAML 格式的任务树，包含：
- 任务 ID、标题、类型、估算
- 依赖关系
- 完成标准

任务粒度：每个任务可在 2 小时内完成（S 级），或 1 天内完成（M 级）。
超过 M 级的必须继续拆分。
```

## 模式 6：Sprint 规划 Prompt

```
你是 Orchestrator，规划下一个 Sprint。

Backlog（按优先级）：
[任务列表]

上个 Sprint 完成率：[X%]
本 Sprint 可用时间：[X 天]

请：
1. 选取本 Sprint 要完成的任务（考虑依赖关系）
2. 识别并行执行机会
3. 标注风险任务
4. 输出 Sprint 计划
```

## 反模式（避免使用）

### 反模式 1：上帝 Prompt
```
# 错误：一个 Prompt 做所有事
"分析需求、设计架构、实现代码、写测试、审查代码"
```
→ 应该拆分为多个专注的 Prompt

### 反模式 2：模糊完成标准
```
# 错误：没有明确的完成标准
"实现用户认证"
```
→ 应该明确：哪些接口、哪些场景、哪些测试

### 反模式 3：过度上下文
```
# 错误：把整个代码库都塞进上下文
"这是我们的代码库：[10000行代码]，请修复 bug"
```
→ 应该只提供相关文件的相关片段
