# 迭代周期 SOP

## 迭代单元

最小迭代单元 = 一个 Task（任务）。
每个 Task 必须满足：独立可验证、单一职责、可在一个上下文窗口内完成。

## 标准迭代流程

```
┌─────────────────────────────────────────────────────────────┐
│                    Task 迭代循环                              │
│                                                             │
│  ┌──────┐   ┌──────┐   ┌──────┐   ┌──────┐   ┌──────┐    │
│  │ GET  │→  │ READ │→  │ IMPL │→  │VERIFY│→  │UPDATE│    │
│  │ Task │   │ Code │   │      │   │      │   │Status│    │
│  └──────┘   └──────┘   └──────┘   └──────┘   └──────┘    │
│      │                     │           │                   │
│      │                     ▼           ▼                   │
│      │               ┌──────────┐  ┌──────┐               │
│      │               │ BLOCKED? │  │FAILED│               │
│      │               └────┬─────┘  └──┬───┘               │
│      │                    │           │                    │
│      │               上报并切换      修复或上报              │
└──────┼────────────────────────────────────────────────────┘
       │
       ▼ 无可用任务时
  ┌──────────┐
  │ 等待分配  │
  └──────────┘
```

## 步骤详解

### Step 1: GET Task
```
TaskGet(task_id)
→ 确认 status == "pending"
→ 确认 blockedBy 列表为空
→ TaskUpdate(task_id, status="in_progress")
→ 记录开始时间到工作记忆
```

### Step 2: READ Code
```
# 先定位，再精读
grep/find 相关文件
→ 读取被修改文件（精确 offset/limit）
→ 读取相关测试文件
→ 确认构建命令和测试命令
```

### Step 3: IMPL（实现）
```
# 最小化原则：只改必要的
Edit/Write 目标文件
→ 每次只改一个逻辑单元
→ 不引入计划外的变更
→ 遇到需要额外变更 → 创建新 Task，不在当前 Task 中处理
```

### Step 4: VERIFY（验证）
```
运行构建命令（必须）
→ 运行相关测试（必须）
→ 检查安全问题（必须）
→ 如果失败 → 修复，重新验证
→ 验证通过 → 进入 Step 5
```

### Step 5: UPDATE Status
```
TaskUpdate(task_id, status="completed")
→ 写入 code_changes 到 LanceDB
→ git commit（如果需要）
→ 检查是否有新解锁的任务（TaskList）
→ 取下一个任务
```

## 阻塞处理 SOP

### 阻塞定义
- 缺少必要信息（需求不清晰）
- 依赖未完成（等待其他 Task）
- 技术障碍（超过 2 次尝试仍失败）
- 权限不足（需要用户操作）

### 阻塞处理流程
```
1. 记录阻塞原因（具体、可操作）
2. TaskUpdate(task_id, status="blocked", description=阻塞原因)
3. 写入 LanceDB incidents（如果是技术障碍）
4. 向用户/Orchestrator 报告（一句话说清楚）
5. 切换到其他可用任务
```

### 阻塞报告格式
```
BLOCKED: [Task ID] [Task Title]
原因: [具体原因，一句话]
需要: [需要什么才能解除阻塞]
建议: [可选：建议的解决方向]
```

## 迭代节奏

| 任务规模 | 估算 | 最大迭代时间 | 检查点 |
|---------|------|------------|--------|
| S（小）  | <2h  | 1个上下文窗口 | 完成时 |
| M（中）  | <1d  | 3个上下文窗口 | 每个子步骤 |
| L（大）  | >1d  | 需拆分为S/M | 拆分后按S/M处理 |

**L 级任务必须拆分**，不允许在单个 Task 中处理 L 级工作。

## Sprint 管理

```
Sprint 周期：1-2 周
Sprint 开始：
  1. 从 backlog 选取任务（按优先级）
  2. 确认 Sprint 目标
  3. 写入 memory/sprints/sprint-{n}.json

Sprint 结束：
  1. 统计完成率
  2. 未完成任务移入下个 Sprint backlog
  3. 写入 Sprint 回顾到记忆系统
  4. 更新 memory/current_state.json
```
