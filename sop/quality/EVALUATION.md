# AI 输出评估框架

## 评估维度

### 1. 正确性（Correctness）权重 40%
| 子维度 | 评分标准 |
|--------|---------|
| 功能正确 | 实现符合需求描述 |
| 边界处理 | 空值/极值/异常路径正确 |
| 无回归 | 未破坏已有功能 |

评分：0（完全错误）/ 0.5（部分正确）/ 1（完全正确）

### 2. 安全性（Security）权重 25%
| 子维度 | 评分标准 |
|--------|---------|
| 无注入漏洞 | SQL/命令/XSS 注入防护 |
| 无硬编码密钥 | 密钥/密码不在代码中 |
| 最小权限 | 不请求超出需要的权限 |

评分：0（有严重漏洞）/ 0.5（有轻微问题）/ 1（无安全问题）

### 3. 最小化（Minimalism）权重 20%
| 子维度 | 评分标准 |
|--------|---------|
| 无多余代码 | 只写解决问题所需的代码 |
| 无过度抽象 | 没有不必要的接口/工厂/策略模式 |
| 无范围蔓延 | 没有超出任务范围的变更 |

评分：0（严重过度）/ 0.5（轻微过度）/ 1（恰到好处）

### 4. 可维护性（Maintainability）权重 15%
| 子维度 | 评分标准 |
|--------|---------|
| 命名清晰 | 变量/函数名自解释 |
| 测试覆盖 | 关键路径有测试 |
| 符合风格 | 与项目现有风格一致 |

评分：0（难以维护）/ 0.5（一般）/ 1（易于维护）

## 综合评分计算

```python
def evaluate_output(scores: dict) -> float:
    weights = {
        "correctness": 0.40,
        "security": 0.25,
        "minimalism": 0.20,
        "maintainability": 0.15,
    }
    return sum(scores[dim] * weight for dim, weight in weights.items())

# 示例
scores = {
    "correctness": 1.0,
    "security": 1.0,
    "minimalism": 0.5,
    "maintainability": 1.0,
}
# 综合分 = 0.40 + 0.25 + 0.10 + 0.15 = 0.90
```

## 评分等级

| 分数 | 等级 | 处理方式 |
|------|------|---------|
| ≥0.90 | 优秀 | 直接合并 |
| 0.75-0.89 | 良好 | 合并，记录改进点 |
| 0.60-0.74 | 一般 | 需要修改后重新评估 |
| <0.60 | 不合格 | 拒绝，重新实现 |

## 安全维度特殊规则

安全维度评分为 0 时，无论其他维度得分多高，综合评分强制为 0（不合格）。
安全问题必须修复，不能用其他维度的高分抵消。

## 持续改进

每 Sprint 统计评分分布，识别系统性问题：
- minimalism 持续低分 → 检查任务描述是否过于模糊
- correctness 持续低分 → 检查完成标准是否足够明确
- security 出现问题 → 立即加强安全检查清单
