# 架构决策规范（ADR）

> 版本: v1.0 | 更新: 2026-05-12
> 参考: Michael Nygard ADR 格式 + ThoughtWorks Technology Radar

## 1. 什么是 ADR

架构决策记录（Architecture Decision Record）：记录重要的架构决策，包括背景、选项、决策和后果。

**记录 ADR 的时机**：
- 技术选型（框架、数据库、消息队列）
- 架构模式选择（MVC vs DDD、单体 vs 微服务）
- 重大设计决策（认证方案、缓存策略）
- 偏离现有规范的决策

## 2. ADR 文件格式

```markdown
# ADR-{编号}: {标题}

**状态**: 提议 | 已接受 | 已废弃 | 已替代
**日期**: YYYY-MM-DD
**决策者**: {角色/人员}

## 背景

{描述问题背景和约束条件，1-3 段}

## 选项

### 选项 A: {名称}
- 优点: ...
- 缺点: ...

### 选项 B: {名称}
- 优点: ...
- 缺点: ...

## 决策

选择**选项 A**，原因：{核心理由，1-2 句话}

## 后果

**正面影响**:
- ...

**负面影响/权衡**:
- ...

**需要关注**:
- ...
```

## 3. ADR 示例

```markdown
# ADR-001: 选择 LanceDB 作为 AI 记忆存储

**状态**: 已接受
**日期**: 2026-05-12

## 背景

AI 智能体需要跨会话持久化项目记忆（任务历史、决策记录、问题记录），
并支持语义检索（"找类似的历史问题"）。

## 选项

### 选项 A: LanceDB（本地向量数据库）
- 优点: 本地运行无需网络、原生向量搜索、零配置
- 缺点: 不支持分布式、社区相对较小

### 选项 B: PostgreSQL + pgvector
- 优点: 成熟稳定、支持复杂查询
- 缺点: 需要额外部署、配置复杂

### 选项 C: 纯文件系统（JSON）
- 优点: 最简单、无依赖
- 缺点: 无语义搜索能力

## 决策

选择**选项 A: LanceDB**，原因：本地运行符合隐私要求，向量搜索是核心需求，
零配置降低使用门槛。

## 后果

**正面影响**:
- 语义检索相似历史任务，减少重复工作
- 本地运行，无数据泄露风险

**负面影响/权衡**:
- 不支持多机器共享（单机使用场景可接受）

**需要关注**:
- LanceDB 不可用时需要降级到文件系统模式
```

## 4. ADR 存储位置

```
memory/decisions/
├── ADR-001-lancedb-memory.md
├── ADR-002-jwt-auth.md
└── ADR-003-microservice-split.md
```

同时在 LanceDB `decisions` collection 中存储向量化版本，支持语义检索。

## 5. ADR 生命周期

```
提议（Proposed）
    │ 团队/用户确认
    ▼
已接受（Accepted）
    │ 被更好方案替代
    ▼
已替代（Superseded）→ 指向新 ADR

已接受
    │ 发现决策有误
    ▼
已废弃（Deprecated）
```

## 6. 何时不需要 ADR

- 常规 CRUD 实现
- 遵循现有规范的代码
- 小的技术细节（变量命名、函数拆分）
- 已有明确规范的场景
