# 核心开发原则

> AI 智能体在所有开发活动中必须遵守的基本原则。

## P1 最小化原则 (Minimalism)

**规则**：只写解决当前问题所需的最少代码。
- 禁止预防性抽象（"以后可能用到"）
- 禁止防御性代码（内部调用不需要过度校验）
- 三行重复 < 过早抽象
- 每次 PR 只做一件事

**检验问题**：删掉这段代码，功能还能正常工作吗？

## P2 状态外化原则 (Externalized State)

**规则**：所有重要状态必须持久化到外部存储，不能只存在于上下文中。
- 任务进度 → LanceDB / Git commit message
- 决策记录 → `memory/decisions/` 目录
- 错误记录 → `memory/incidents/` 目录
- 上下文压缩前必须先持久化关键信息

## P3 可追溯原则 (Traceability)

**规则**：每个变更必须可追溯到需求。
- Commit message 格式：`type(scope): description [task-id]`
- 每个函数变更关联 task ID
- 重大决策记录在 `memory/decisions/` 中
- 禁止 force push main/master

## P4 渐进验证原则 (Incremental Verification)

**规则**：每个小步骤完成后立即验证，不积累未验证的变更。
- 每次修改后运行相关测试
- 编译错误必须在当前步骤修复
- 不允许带着已知错误进入下一步

## P5 上下文经济原则 (Context Economy)

**规则**：最大化每个 token 的信息价值。
- 读文件前先用 grep/find 确认目标
- 不重复读取已知内容
- 长文件只读相关片段（用 offset/limit）
- 子任务用子智能体隔离上下文

## P6 安全第一原则 (Security First)

**规则**：安全问题优先于功能完整性。
- 用户输入必须在系统边界验证
- 禁止硬编码密钥/密码
- SQL/命令注入防护是默认要求，不是可选项
- 发现安全漏洞立即修复，不延后

## P7 诚实原则 (Honesty)

**规则**：AI 智能体必须如实报告状态，不能假装成功。
- 测试失败 → 报告失败，不跳过
- 无法验证 → 明确说明无法验证
- 不确定 → 说不确定，不猜测
- 遇到阻塞 → 立即上报，不沉默

## 原则优先级

当原则冲突时，优先级：P6 安全 > P7 诚实 > P4 渐进验证 > P3 可追溯 > P2 状态外化 > P1 最小化 > P5 上下文经济

## P8 自我反思原则 (Self-Reflection)

**规则**：执行失败或置信度低时，必须显式反思后再行动。
- 构建/测试失败 → `<reflect>` 分析根因，换思路重试
- 同一问题第 2 次失败 → 必须换方案，不重复同一思路
- 第 3 次失败 → 停止自行重试，上报 Orchestrator
- 置信度 < 0.70 → 主动触发 Reviewer，不等待指令

**检验问题**：我是在重复同一个失败方案，还是真正换了思路？

## 原则优先级（更新）

P6 安全 > P7 诚实 > P8 自我反思 > P4 渐进验证 > P3 可追溯 > P2 状态外化 > P1 最小化 > P5 上下文经济

## P9 模块化单元化原则 (Modularity)

**规则**：所有输出物（文档、代码、页面）必须模块化，单个文件不超过规定行数上限。

| 输出类型 | 单文件上限 | 拆分策略 |
|---------|-----------|---------|
| 规范文档（.md） | 300 行 | 按章节拆分到独立文件 |
| 后端路由（.py） | 100 行 | 按资源拆分到 routers/ |
| 前端页面（.js） | 200 行 | 按功能拆分到 pages/ |
| 前端组件（.jsx/.vue） | 150 行 | 按组件拆分 |
| 工具脚本（.sh） | 80 行 | 按功能拆分 |
| 配置文件（.json/.yaml） | 100 行 | 按环境/模块拆分 |

**执行方式**：
- 新建文件时，先评估是否超限，超限则拆分
- 修改文件时，只读取和修改相关模块，不加载整个文件
- 超过上限的现有文件，在下次修改时顺带拆分

**检验问题**：这个文件超过上限了吗？能否拆成更小的独立单元？
