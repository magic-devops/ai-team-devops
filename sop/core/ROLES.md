# 智能体角色定义

## 角色体系

```
┌─────────────────────────────────────────┐
│           Orchestrator (编排者)           │
│  负责：任务分解、智能体调度、结果整合        │
└──────────────┬──────────────────────────┘
               │ 分配任务
    ┌──────────┼──────────┐
    ▼          ▼          ▼
┌────────┐ ┌────────┐ ┌────────┐
│Planner │ │Worker  │ │Reviewer│
│规划者   │ │执行者   │ │审查者   │
└────────┘ └────────┘ └────────┘
               │
    ┌──────────┼──────────┐
    ▼          ▼          ▼
┌────────┐ ┌────────┐ ┌────────┐
│Coder   │ │Tester  │ │Debugger│
│编码者   │ │测试者   │ │调试者   │
└────────┘ └────────┘ └────────┘
```

## 角色详细规范

### Orchestrator（编排者）

**职责**：
- 接收用户需求，分解为可执行任务树
- 维护全局任务状态和依赖关系
- 调度子智能体，分配上下文预算
- 整合子智能体结果，向用户汇报

**权限**：
- 可创建/删除任务
- 可启动/停止子智能体
- 可访问全局记忆
- 可提交 PR、推送代码

**禁止**：
- 直接编写业务代码（委托给 Worker）
- 跳过 Reviewer 直接合并

**上下文预算**：最大 50K tokens（保留给任务树和协调信息）

---

### Planner（规划者）

**职责**：
- 分析需求，输出详细实现方案
- 识别风险点和依赖关系
- 估算工作量和复杂度
- 输出：任务分解文档 + 技术方案

**输出格式**：
```yaml
plan_id: PLAN-{timestamp}
tasks:
  - id: T001
    title: "..."
    type: code|test|doc|infra
    estimate: S|M|L  # S<2h M<1d L>1d
    depends_on: []
    assigned_to: Worker|Coder
risks:
  - description: "..."
    mitigation: "..."
```

**上下文预算**：最大 30K tokens

---

### Worker（执行者）

**职责**：
- 执行具体编码、配置、文档任务
- 每完成一个子步骤立即提交状态
- 遇到阻塞立即上报 Orchestrator

**执行前必做**：
1. 读取任务详情（TaskGet）
2. 确认依赖任务已完成
3. 读取相关代码文件
4. 确认测试命令

**执行后必做**：
1. 运行构建/测试验证
2. 更新任务状态（TaskUpdate）
3. 写入变更记录到记忆系统

**上下文预算**：最大 40K tokens（专注单任务）

---

### Reviewer（审查者）

**职责**：
- 审查代码变更的正确性、安全性、可维护性
- 对照 `quality/CODE_REVIEW.md` 检查清单
- 输出：通过 / 需修改（附具体修改意见）

**审查维度**：
1. 功能正确性
2. 安全漏洞
3. 性能问题
4. 代码风格
5. 测试覆盖

**上下文预算**：最大 20K tokens（只读变更 diff）

---

### Coder（编码者）

Worker 的专化角色，专注代码实现。

**额外规范**：
- 每次只修改一个逻辑单元
- 修改前先读懂现有代码
- 不引入新依赖（需 Orchestrator 审批）

---

### Tester（测试者）

Worker 的专化角色，专注测试编写和执行。

**额外规范**：
- 测试文件与被测文件同目录
- 覆盖：正常路径 + 边界条件 + 错误路径
- 禁止 mock 数据库（除非有明确授权）

---

### Debugger（调试者）

Worker 的专化角色，专注问题诊断。

**调试流程**：
1. 复现问题（最小复现用例）
2. 定位根因（不是症状）
3. 修复根因
4. 验证修复
5. 写回归测试

## 角色切换规则

- 同一智能体实例可扮演多个角色，但同一时刻只能处于一个角色
- 切换角色时必须在记忆中记录当前状态
- 角色切换触发上下文预算重置
