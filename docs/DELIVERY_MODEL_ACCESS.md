# 项目权限、模型调用与会话一致性

本页描述已经实现的行为；完整范围及未完成项见 [DELIVERY_WORKBENCH.md](DELIVERY_WORKBENCH.md)。

## 业务访问

`requirements`、`tasks`、`issues`、`sprints`、`models` 和 `llm` 接口要求有效身份及显式 `X-Project-Id`。支持 Bearer JWT，以及 HMAC 中间件验证通过的 API Key 签名身份；只有 `X-Api-Key` 不构成认证。身份重新检查当前数据库用户状态，停用用户不能继续使用旧密钥。

- 项目成员可读；项目管理员、开发、运维、产品经理可写；分析及只读角色不能写。租户管理员限本租户，超级管理员沿用既有全局权限。
- 提供商凭据、默认模型、任务模型等配置只能由项目管理员或相应更高权限维护。模型调用需要业务写权限。
- 请求不能通过正文或查询参数改到另一项目，关联需求、任务、迭代必须属于当前项目。无权访问的项目、其他项目的记录和缺失记录均不能写入。
- 这些入口不会凭随机项目头隐式创建项目；项目初始化接口保留原有独立行为。
- `GET /api/v1/tasks/{task_id}` 返回当前项目的实际任务及 UI 扩展字段，与列表单项一致，缺失或跨项目返回 404。
- SDK `ManagerClient.get_task(task_id)` 与 CLI `sop task show ID [--json]` 使用同一详情入口，沿用当前身份及项目；失败明确返回，不用本地记录冒充远端结果。

共享异步依赖在同步处理线程启动前绑定作用域，完成后复位；因此 HMAC 请求也使用已授权项目的数据路径，不依赖中间件顺序碰巧正确。

## 有效模型配置

模型选择顺序为显式 `model`、`role_models[task_type]`、保存的项目默认模型。任务拆解使用 `task_type=plan`；评审等调用可按对应任务类型配置。尚未保存项目配置时保留原有环境路由和回退兼容。已保存配置只调用选中提供商，缺失、禁用、没有凭据、不支持的提供商明确失败，不会偷偷使用另一项目或全局凭据。

当前调用适配器为 Anthropic、OpenAI 兼容 API、Ollama。自定义 OpenAI 兼容服务使用 `provider=openai` 及其 `base_url`。目录中的 Google、DeepSeek 名称本身不等于独立适配器已实现。Anthropic/OpenAI 调用仍需运行环境安装对应 SDK；当前隔离验收环境未安装这两个 SDK，定向测试使用 SDK 替身，本地 HTTP 联调使用 Ollama 协议桩。

Chat、云 Embedding、本地 Embedding 失败后的云回退，以及数据问答的模型路径使用同一项目配置。已有本地 Embedding 可继续独立运行。任务预览保存实际返回的模型、提供商和用量。缓存按租户、项目、配置及实际凭据指纹隔离；命中返回零新增用量，不重复计费、不修改原响应。错误响应不透出上游凭据和异常正文。

`POST /models/providers/{name}/test` 是配置/端点连通性检查，不能代替一次真实模型推理。`llm_gateway_v2` 中治理模拟策略尚未与全部实际调用统一，不将其页面配置冒充实际生效。

## 配置存储与兼容

配置存储在请求数据根目录下 `model-configs/<scope SHA256>.json`。摘要输入是 JSON 数组 `[tenant_id, project_id]`，使用无空格分隔符 `(',', ':')`。即使两个项目未填写本地路径、共用同一目录，其模型配置仍分离；项目标识不会直接成为文件路径片段。

旧根目录 `models.json` 没有所有权信息，默认不导入。确需复用时，运维须同时设置 `SOP_LEGACY_MODELS_TENANT_ID`、`SOP_LEGACY_MODELS_PROJECT_ID`，仅完全匹配的项目可读取该旧文件。该项目首次保存写入新隔离路径，旧文件保留；公开配置 `routing_source` 区分 `environment`、`legacy_project`、`project`。

普通凭据可直接保存。环境引用只接受本项目专属名字：`SOP_LLM_CREDENTIAL_<scope SHA256前16位大写>_<NAME>`，其中 NAME 为大写字母开头的大写字母、数字、下划线组合。服务端函数 `credential_env_prefix()` 返回当前项目的前缀，由运维在服务器设置相应变量。任意 `${SECRET_KEY}`、`${DATABASE_URL}`、全局模型凭据引用或其他项目的引用均拒绝；历史配置含非法引用也明确失败，不能继续解析服务端秘密。旧引用须由运维改为对应项目专用变量或项目凭据。

## 会话与页面

前端请求固定起始账号、登录修订和项目。旧请求不能清除新登录、恢复已退出账号、覆盖新项目资料、显示旧项目结果，或把原写操作重发到新账号。相同上下文共享认证恢复，不同上下文独立；用户明确切换项目后不再被 `/auth/me` 的默认项目覆盖。

主控制台及所有独立子应用使用同一会话查询容器：切换时清除缓存并重新挂载观察者，避免已挂载页面继续展示旧结果。登录页同样固定探测的登录修订，迟到的认证失败不会清除之后的新登录。请求失败仍保留业务表单已有的重试、草稿和冲突恢复机制。

## 验收证据（2026-10-16）

- Manager 199 项通过，含原交付 74 项、业务访问 69 项、模型 53 项、数据问答 3 项；Web 202 项通过，含请求竞态、缓存与观察者生命周期。SDK/CLI 定向 17 项通过，真实隔离 HTTP 返回相同任务详情。
- 一次独立审查发现 3 个 Important：观察者保留旧结果、同目录配置串项目、任意环境秘密外传；均复现并修复。观察者问题还在实际浏览器验证修前显示 A、修后显示 B，没有追加重复泛扫。
- 本地 HTTP 证据 `.sop-runtime/model-transport-proof.json`：两次聊天只发生一次模型网络请求，缓存新增用量 0；相同 AI 预览凭证仅一次模型请求、未自动创建任务；两个空路径项目的配置互不影响；禁用项目返回 503 且无模型网络请求。
- 实际工作台切换项目、空态、切回恢复、模型建议预览及用量显示验证；390px 长验收条件多选字段溢出已修正，弹窗正文宽度与滚动宽度均为 311px。截图 `model-plan-preview-desktop.png`、`model-plan-preview-mobile.png` 位于隔离运行目录，预览草稿随后取消。
- 保护路径不隐式创建项目的变体测试还覆盖了 delivery 与 analytics/nlq，中间件不会在这些入口抢先调用项目初始化。

本地协议桩不执行真实 AI 推理，不据此宣称厂商生产凭据、全部厂商适配器或全产品完成。
