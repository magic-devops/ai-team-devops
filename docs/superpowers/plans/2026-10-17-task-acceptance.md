# 任务验收与独立执行实施计划

设计依据 [任务验收与独立执行](../../DELIVERY_TASK_ACCEPTANCE_DESIGN.md)，基线 `5fb9f77`。用户授权直接按合理设计增强，无历史别名或假需求；本阶段验证后统一 commit、不 push，完整目标继续。

1. **契约与正式模型**：先验证文本条件、明确需求索引、空草稿和真实可选需求的 RED；新增 Task SQL 自身条件及所有普通写通道共享校验。提供显式幂等结构升级，旧数据不补造条件，验证启动与 CLI 边界。
2. **共享交付定义**：纯模块解析有效条件与来源；manual/native/preview/progress/inbox 消费同源定义。原生快照不含状态/日期；需求不可读或关联失效关闭动作。ORM/Core 事务内永久作废旧证据，验证 A→B→A、依赖、跨作用域与纯读。
3. **全任务执行链**：解除 Manager 必须有需求的限制，保留原 runtime 身份、目标、CAS、幂等、测试与人审门禁；独立证据留在原 execution，失败复用 Issue→需求。
4. **统一任务详情**：任务自身条件逐条编辑，需求关联单独呈现；复用执行面板和内容组件，独立详情聚焦、错误/缺失状态、并发草稿、精确返回和390px键盘操作。
5. **验证与收尾**：root 运行相关全量/定向测试、类型检查与生产构建；公开实际独立派发/测试/人审、失败回流和 UI 留证。源码冻结后最多一次独立增量审查，修复后定点复验。更新 OpenAPI/SDK/CLI、功能清单与记忆，库存散列保存证据后清理阶段 scratch，全部阶段更改 commit。

文件归属：backend owner 管 delivery 业务模块及 Manager 业务测试；runtime/API owner 管 SQL Task、普通 CRUD、同步/导入、共享输入校验、显式升级和 SDK/CLI；UI owner 管 Web 源码及测试；root 管 typed Python 契约、OpenAPI、设计/记忆及最终验证。共享文件变更先协调，阶段期间不单独提交。

团队 runtime 稳定身份、项目组合/归档、可信 CI/生产模型、版本与质量发布、真实部署回退和智能运维闭环继续保留后续验收，不随本阶段局部通过被标成完成。
