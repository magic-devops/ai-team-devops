# 业务权限、有效模型配置与会话一致性

本增量继续既有完整建设计划，不改变产品范围。前一目标轮完成任务计划验收；缓存问答只核验忽略规则，本轮恢复下一项待办。

## 设计与验收边界

- 旧需求、任务、问题、迭代入口必须使用当前有效身份、显式项目及项目角色；已验证 HMAC 可兼容，裸密钥不构成身份。读写及模型配置权限分开，调用期间绑定并复位项目数据目录。
- 模型配置必须进入真实任务拆解调用路径。显式模型优先，其次任务类型配置、保存的默认模型；无配置时保留环境路由。配置的服务商、地址、凭据、禁用状态均生效。失败明确返回，不能冒充另一个模型成功。公开响应不含密钥，缓存隔离项目和配置。
- 前端请求从开始到结果消费固定账号与项目。只有该请求自己的认证恢复或默认项目绑定可以更新上下文；账号/项目切换后旧响应不能清除认证、写用户资料、选项目、显示旧业务结果或重发写操作。相同上下文的恢复请求共享，不同上下文独立。
- 保留现有界面与主题；本轮行为变更在真实页面上验证重新登录、项目切换和工作台加载，不新增无依据的可视化。
