# 外部协作工单

本阶段源码将外部智能体和开发工具的工作入口收敛到项目中的真实任务。工单记录派发与接单，交付报告记录外部提供的证据，人工验收仍使用任务已有的验收流程。三者各自保留原件，不能相互替代。

## 操作流程

1. 选择项目与已有任务，确认任务目标、负责人、依赖和验收条件。没有可选任务时先创建任务，不会自动生成临时任务编号。
2. 选择项目团队中已登记的智能体或工具，复核固定工作包后派发。工作包使用明确采用的设计版本，包含原文和摘要；后续保存设计新版本不会悄悄替换它。
3. 导出工作包供外部工具使用。接单人使用有项目权限的账号明确接单，填写实际进展与说明。派发、接单和导出均不表示工具进程已启动。
4. 接单人通过同一任务提交交付报告，逐项填写验收条件和测试结果，并提供证据。确认外部工作已停止，将该报告的明确编号和摘要关联到工单后，进入人工验收；失败或未知的测试不能被自动填成通过。
5. 在已有任务验收入口确认交付或要求修改。交付问题继续进入既有问题排查、诊断和需求池流程。

## 取消与恢复

尚未接单的工单可以取消。已接单的工单先请求取消，再由持有人明确释放并说明外部工作已经停止；这一说明保留为外部回报，不会伪装成运行器确认的进程停止证据。超时、失联、设计变更和资源停用都不会自动释放占用或触发重派。

任务或设计发生变化后，旧工作包保留为历史原件，不能据此提交新定义的交付。需要先收敛原工单，再按新定义派发。切换项目或账号后，不复用其他作用域的缓存或待确认操作。提交结果未知时，恢复原请求，保持原编号、版本和幂等键。

规划中或暂停的项目不能新派发或新接单。暂停时，已有工单仍可回报实际进展、请求取消和释放，便于收敛正在进行的工作。

归档前应收敛所有仍占用任务的工单。账号撤权即时生效；已撤权持有人不能继续写入进度或释放事实，需要恢复合适授权后处理。此阶段不增加绕过账号撤权的释放通道。

## 外部平台边界

工作包可以用于 WorkBuddy、OpenCode、Zed、Codex、Hermes、Harness、DSH、OpenClaw 等外部工作环境。项目资源名称只是团队登记信息；导出工作包不代表这些平台已经安装、鉴权或自动接入。

本机运行器支持的工具仍使用已有执行计划与运行观测入口。外部工单与本机执行使用同一任务的互斥检查，避免同时重复启动。没有经核实的适配器或消费回执时，页面不会宣称已经通过远程 Endpoint 执行。

工作包中的仓库链接是派发时固定下来的参考资料，标记为 `registered_unverified`；它们不证明实际检出目录、Git 提交或代码归属。后续编辑项目资源目录不会替换旧包中的参考链接，也不会据此自动执行仓库操作。实际代码纳入与构建来源核验仍是后续独立工作。

旧的文件式 A2A 与 agent-run 公开接口退役，不导入为任务完成或验收事实，也不删除原有用户文件。运维中的历史轨迹明确保留为未核验的外部回报。完整新接口以 [接口设计](CANONICAL_TOOL_DISPATCH_DESIGN.md) 为准。

## SDK 与命令行

SDK 的 `delivery_work_order_current`、`delivery_work_order_preview`、`delivery_work_orders`、`delivery_work_order` 和 `delivery_work_order_packet` 对应当前准入、只读预览、单页列表、明确原件和完整工作包。工作包下载会核对项目、工单及实际 JSON 内容摘要，失败时拒绝作为有效包输出。

命令行入口为 `sop delivery work-order-current --task <真实任务编号>`、`work-order-preview --task <真实任务编号> --file <完整预览JSON>`、`work-orders`、`work-order --id <工单编号>` 和 `work-order-packet --id <工单编号>`。分页使用 `--limit`、`--cursor`；不会自动遍历整个目录。

所有工单写动作使用 `sop delivery work-order-command --file <完整原命令JSON>` 或 SDK `delivery_work_order_command`。文件必须明确包含 `action`、`expected_version`、`idempotency_key` 与 `payload`，正文最大 64 KiB；不会根据当前页面重新生成版本或请求键。响应丢失后保留文件，用同一原件恢复。重复键、非有限数字、错误作用域、数字代替停止确认，以及把进度写成终态成功，都会被拒绝。

`work_order.report` 和 `work_order.release` 的停止确认必须是明确的 `stopped_attestation: true`。命令行不会替用户或智能体补上这个确认。

## 从项目待办处理外部交付

项目待办沿用“我的事项/团队事项”。实际接单人的工单进入工作事项，自报受阻同时进入受阻事项；这不会改变原任务负责人或审批权限。报告保存在任务后，还需要明确停止确认并关联到工单，才进入外部交付待验收。人工退回继续显示返工和已有问题，点击可进入原报告查看结论。

工单目录分别展示工单状态、自报进展和人审结论。百分比未知与尚未报告分别显示，报告100%不会自动计入验收通过。桌面和窄屏的“查看报告/退回意见/验收记录”直接定位对应报告，返回保留来源位置。

任务切换会清理旧报告、工单及自动填写标记；只有明确的新目标才携带对应编号。索引升级后沿已有明确重建入口刷新待办，读取不会自动修改索引。具体规则见 [外部交付待办设计](EXTERNAL_DELIVERY_ATTENTION_DESIGN.md)。
