# 团队运行关联的原请求恢复

本阶段按用户指令只推进源码与设计。应用、测试收集或执行、类型检查、构建、浏览器和实际工具验证均后置。

## 交互流程

在原团队详情中编辑关联，继续使用工作区、配置版本和实际提供方的核对流程。点击保存前，将完整 action、payload、原版本和原幂等身份写入当前账号、租户、业务、项目、浏览器会话及成员范围的操作原件；本地保存失败时不发送请求。

同一成员的绑定和解绑共用一个待处理槽位。发送中不能重复提交；结果未知时锁定新编辑，只能使用原件恢复；收到严格匹配回执后显示确认结果，应用回执失败仍保留已知成功，不重新写入。只有明确拒绝时允许丢弃原件，或读取最新关联、核对后明确采用新依据继续编辑。读取最新事实本身不构成原操作失败的证明。

编辑窗口为已安全保存的原件提供“保留操作，稍后恢复”。该动作只退出当前编辑界面，同一所有者继续保留控制器和操作原件，迟到响应不再调用已卸载编辑器；团队详情仍可处理原回执。未知请求不被清除，也不因此另建写入。

团队页列出本会话待恢复的成员操作，并支持定位对应成员。成员详情不可读或已不存在时仍提供原件恢复入口；实际请求与回执读取始终由服务端当前权限决定。人员与无原件的失效身份不进入运行配置编辑。

## 稳定性边界

- 复用现有命令控制器、固定会话请求和服务端幂等合同。绑定原件严格限定 member_id/workspace_id/agent_id/agent_version；解绑只含 member_id。身份、版本、键及大小都验证，拒绝额外字段与失效本地原件。
- ACK 必须精确匹配项目、动作、成员、应用版本、引用和 result:null；异常或不完整 ACK 保持结果未知，不能关闭原件或新建写入。
- 存储采用原值比对，避免迟到的旧控制器覆盖新操作。成功回执持续保留，直到当前界面明确应用并结束操作。
- 应用器等待当前活动项目查询的严格刷新，再实际读取运行目录并核对项目和版本；任何异步刷新失败均向上传递，不能先清回执。原有其它流程的默认刷新行为不变。
- 编辑、读取、采用、关闭及异步回调均绑定当前项目、成员、会话、路由、编辑实例和控制器。发送中切换上下文使原控制器失效；旧响应不能关闭新窗口或调用新上下文的保存回调。
- 路由或控制器范围变化时，按该范围重新挂载编辑与恢复界面，旧 Promise 的同步锁和忙状态不会占用新界面。
- 新写入检查当前关联权限；原件恢复不以最新目录或当前配置版本重建 payload，不自动换版本或换幂等键。
- 恢复范围为同一已授权浏览器标签页会话。不会跨账号自动恢复，也不上传本地原件。损坏或不可读原件明确显示阻塞，不能静默清除。

## 检查与后续

先补实际控制器、存储、组件与团队入口的检查定义，再实现。覆盖超时、提交前持久化失败、丢 ACK、错误 ACK、明确拒绝、恢复后仍拒绝、组件卸载、项目/路由切换、双击、权限变化、迟到响应、损坏原件、成功应用失败及失效成员入口。服务端回归定义核实原版本/原键重放返回原 ACK，不改变当前已被新操作修改的关联。检查定义并不代表已执行结果。

实际运行、键盘、窄屏、浏览器刷新和外部工具连接待验证窗口恢复后核验。其它工具自动适配与完整研发全链路继续推进。
