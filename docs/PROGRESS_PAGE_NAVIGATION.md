# 开发进度明细的分页与失败恢复

任务 `T-progress-page-navigation`，基线 `f9b4402bb9126761988ad1cdb56575ba080f7b2f`。延续已确认的紧凑工作台与真实进度事实，不增加任务、进度或审批模型。

现有基线目录、固定快照和基线差异列表只能首页/下一页；分页读取失败后分页条消失，部分“刷新”实际重置到首页。游标深链的显示页号也并非服务端提供的实际位置。

本阶段补以下源码：

- 统一上一页、首页、下一页。上一页仅使用同一浏览范围内成功读取响应给出的 `next_cursor` 反向关联，不计算或猜测游标。深链或未保留上页时明确提示，可返回首页。
- 位置仅保留在当前组件内存，最多 32 条，每条游标限 16 Ki 字符，不保存行内容、令牌、持久草稿或已验证状态。组件重建后不声称仍有上页。
- 身份、项目、会话、来源类型/ID、分类/范围和实际快照依据/比较代次分别隔离；切换后立即不使用旧关联。短暂页面读取失败不抹除同一来源的已知关联。每次导航仍通过原来的身份和未决操作保护，并重新请求服务端。
- 其他标签页的同身份设置存储事件不会永久禁用分页；真实身份变化仍使旧宿主回调失效。
- 基线目录的首页会读取新目录截点，之后按新的 `as_of` 重置位置关联；不伪装成可以重建旧截点的首页。固定快照与比较页继续使用既有精确来源和代次。
- 读取失败仍保留明确的返回入口。重试只重新读取当前目标，首页才重置游标；不再把“刷新”暗中当成回首页。403/404 继续抑制缓存行、计数和分页入口。
- 区分未读取、本页空、范围空和本类无差异。成功时显示本页条数及完整总量，不把 URL 页号冒充服务端精确页次。仅改变浏览位置，不改变质量、验收或完成事实。
- 窄屏分页条可换行，未知位置、错误和空态中英日一致。非法/无限页号规整，仅用于安全的浏览参数。
