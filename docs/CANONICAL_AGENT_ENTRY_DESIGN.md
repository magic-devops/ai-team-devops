# 智能体运行入口与原操作恢复

阶段 `T-canonical-agent-entry`，承接 `6c8f59d`。用户要求优先完善代码和交互，运行验证等待资源和共享窗口恢复，本阶段不启动测试、类型检查、构建、浏览器或服务。

## 操作路径

Agent运行中心读取正式项目中的执行意图，分页展示任务、运行、状态及关联成员。运行列表、运行跟进和待处理运行共用这份事实；后两者明确限定当前加载页，不从有限窗口推算全项目成功率。成员配置按需读取正式团队运行绑定，独立工作区继续保留。

用户从任务配置派发，进入同一条正式链：保存执行意图 → 同步到执行器 → 启动与观测 → 测试事实 → 人工验收。保存意图不表示执行器已经启动，执行完成不表示测试或人工验收通过。列表直接打开精确执行详情、关联任务和成员配置，不通过临时生成的任务ID创建并行台账。

进入正式详情携带受限本地返回地址，保留运行中心的模块、筛选、分页游标及观测抽屉位置。正式工作台提供返回运行中心按钮，关闭执行详情回到原列表；目标项目必须精确匹配，拒绝外链、重复项目和嵌套非法返回。

原Agent运行中心的手工成功、固定通过门禁、模拟证据与手工心跳操作退出此产品入口。旧Agent JSON和A2A协议仍有独立接口与外部工作进程能力，它们的登记结果不被映射成正式任务验收。A2A消费者、外部身份映射和运维自愈仍需后续阶段接入，不能据此宣称所有执行入口统一完成。

## 运行干预

启动、重试、请求停止和审批均使用现有正式预览与命令。用户先填写原因，再核对运行、尝试、观测版本和审批身份，最后明确提交。预览和读取最新事实只读；重新预览前撤销旧证明。

命令在发送前保留原正文、原版本和幂等键。同一执行使用一个恢复槽，按租户、用户、登录代次、项目及执行隔离，不存token。当前标签刷新后仍可以恢复同一操作。存储缺失、损坏或不可写时停止新提交，不推测原操作结果。

未知结果只允许读取原运行或重试原请求。读取当前状态不能充当原命令回执；原请求重试后即使收到明确4xx，也继续保留未知状态。首次明确拒绝可保留草稿，读取新预览并明确采用后再次确认。

回执严格核对项目、动作、执行资源、原版本和真实运行结果。启动类回执核对工作区与尝试；重试对应原尝试加一。取消可以合法没有运行，停止是否落实继续由执行器证据决定。Manager回执重放与runtime跨库回执恢复分别判断，不要求两个标记相同。

回执确认后只清理本地恢复槽。清理失败显示已确认，提供只读清理动作，不再发送命令。新运行事实读取失败也不把已确认操作改回失败。执行详情或runtime首次读取403时，恢复入口继续可用，旧业务缓存收起，新操作停用。

## 验证与边界

源码证据位于 `.sop-runtime/delivery-evidence/canonical-agent-entry/`。本阶段检查实际后端合同、消费者回调和源文件摘要，并编写后置回归定义。静态审查不能替代运行、类型、视觉、权限或生产验证。

运行控制的持久恢复不自动覆盖派发计划的queue、首次sync、团队绑定、人工验收和其他编辑器；各入口仍需逐一完成同样的原件恢复审查。后续从阶段提交重新固定完整源码，按共享资源窗口执行检查。精确设计版本采纳、项目创建、代码纳入CI关系、Reflection和全部生产联调仍在完整目标中。
