# 统一派发与返工反馈

阶段 `T-external-tool-workflow`，基线 `e76b81cefd5276cff15fe4700a389dc4e5b18f73`。当前阶段按用户要求先完善代码与交互，测试、类型、构建、应用与浏览器验证继续后置；本文不是实际接入或运行通过的证明。

## 已核实的断点

外部工单 W 保存完整工作包与正式接单身份，但 `executor.tool` 仅为登记文字，现有 Agentd/Hermes 没有消费 W 的运行所有者。直接按该名称启动进程会缺少 W 消费授权、启动 fencing、恢复及物理停止事实。

已有原生执行 E 具备正式成员绑定、固定 Agent 配置与版本、工作区及主机/设备、测试节点、持久交接 H、控制与验收。计划编辑器已能按成员绑定预填，但派发入口没有统一发现、选择和预选消费者。活跃 W 与原生 E 已有互斥，不能用切换界面绕过。

原报告 S 被要求修改后已有不可变审核结论与关联 Issue。下一次 W 工作包和 E→Core→Agent 输入没有消费这些反馈，用户仍需手工转述。现有 W 精确详情已返回固定目标与说明，但页面只在新建草稿中展示完整定义，接单前难以直接核对。

## 选择与归属

| 路径 | 归属与行为 |
| --- | --- |
| 平台执行 | 从当前项目的真实成员绑定、Agent 版本和目标能力选择；复用 E 的预览、确认、H、启动、日志、测试与验收。 |
| 外部协作 | 明确选择 W，保存固定工作包、由授权账号接单和自报进度；派发与导出仍不表示进程已启动。 |
| 返工反馈 | 显式选择同项目、同 Task 的原 S 与退回结论，作为固定参考输入；不成为当前需求、测试通过或人工验收事实。 |

不为简化操作增加另一套业务 Task 或偷偷在活跃 W 下创建 E。完整 W 自动运行器仍需独立的消费授权、启动恢复与停止证明，不能把当前受限 argv 执行等同于操作系统沙箱或工单授权。

## 用户流程

1. 从任务、外部协作目录或精确退回报告进入统一派发。保留明确项目、Task 和安全返回位置。
2. 根据当前真实能力选择平台智能体或外部协作。匹配正式成员后带出工作区、Agent 与版本；多目标继续明确选择。能力不可用时显示原因及配置入口，不静默改变执行方式。
3. 返工派发显示被选原报告、退回意见和问题引用。当前任务要求与旧报告的自报测试分开，用户核对后继续。
4. 平台路径进入原计划编辑器，保留测试方案、预览与确认。外部路径进入 W 表单，固定内容在详情与接单前可直接查看，保留原工作包下载。
5. 未知结果恢复同一原件；确定冲突读取最新后明确采用。关闭草稿、更新当前数据与确认原操作分别处理。

## 固定反馈合同

客户端只提交可选的 `feedback_reference`，三个字段为 `submission_id`、`submission_digest`、`decision_id`。S/D 身份使用至多 64 字符的正式标识，摘要为 64 位小写十六进制；省略或 null 表示本次没有选择反馈，不推断最新报告。该引用可用于 E 的预览/入队，以及 W 的预览/新建；不接受客户端编造的反馈正文。

Manager 精确读取同项目、同 Task 的 S、不可变 `request_changes` Decision 与关联人工 Review，核对完整原件、摘要及当前读取权限。S 摘要标识完整 Manager 原件，不能用 S.payload 的摘要替代。明确选定的失效历史报告可作为修改参考，但不能成为当前验收依据。

固定内容为 `feedback_context` 与 `feedback_context_sha256` 成对出现：schema 为 `manager.delivery-feedback.v1`，包含 project_id、task_id、原三字段 reference、完整 submission.definition/payload，以及 decision 的 decision/review_id/comment/reviewer(id/name)/created_at/issue_id。摘要针对 sorted-key、compact、finite UTF-8 JSON；完整反馈至多 65,536 字节，超过返回 `feedback_context_budget`，不截断。没有反馈时不制造空上下文，允许 DTO 将可选字段序列化为 null。

E 业务条目只保留明确引用、内容摘要与反馈来源权限范围，完整正文在预览及固定 H/Agent 输入；W 工作包保留完整上下文与摘要，精确详情可直接阅读，列表维持摘要。读取、重试及延迟启动继续检查原固定来源权限；恢复已有 H 时使用固定原件，不重新读取最新 S 拼装内容。

选定反馈时，权限范围必须是明确列表，空列表与缺字段不能混同。H 的 envelope.source 也固定 `feedback_runtime_scopes`，使它随已有完整 managed request 摘要一起受保护；不能只比较两个可同时损坏的权限列表，或仅依赖未重算的计划摘要。W 的反馈权限与合并权限已在完整 original 摘要内。该范围用于来源读取权限，不授予 Agent 新权限。

快照纳入 W packet 与 E plan/H 原件及其预览摘要，不能在派发或重放时替换为当前最新报告。它保留报告来源、条件与测试自报、退回意见和问题引用；不自动复制旧通过结论到新测试，不关闭 Issue，不改写 Task 定义。若选择的是旧定义反馈，界面明确其来源与当前定义的区别。

Core 的本机、配对与实际 Agent 输入消费同一固定反馈，核对完整内容、引用、项目/Task 与规范摘要；有字段但损坏时拒绝，不截断、猜测或静默丢弃。反馈是任务数据，不是替代 Agent 配置的系统指令。完整 Agent 输入仍受现有总预算限制。

## 交付边界

Manager 维护反馈来源及 E/W 业务准入；Core 承担实际运行输入验证；Web 维护明确选择、固定预览和恢复；SDK/CLI 接受同一正式引用并保留原请求，不另建任务或回执语义。

独立 W/S 原件在父查询失败时的全面恢复、旧报告草稿的受控复用、SDK 完整会话 journal/严格回执和新 W 自动运行器分别记录后续范围，本阶段不将它们宣称已完成。参考平台按实际配置能力接入，不按名称声称已安装、在线或验证成功。
