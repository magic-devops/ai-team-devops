# 项目与任务的引用选择、分配和读取恢复

任务 `T-assignment-reference-workflow`，基线 `5409d9aa7eb1229cca9541a5799d1e49f997319c`。继续既有项目、团队、需求拆解与任务分配流程，补共享选择器的具体缺口，不另建人员或任务模型。

## 当前流程与本轮行为

项目目标、负责人、需求与任务编辑、团队成员任务的负责人维护、需求筛选、拆解批量负责人、前置任务、里程碑和进度范围复用正式引用查询。原选择器把失败读取的缓存合并成可选项、忽略已选项读取错误，并将上次成员列表当作候选。当前输入与异步读取也缺少统一的会话、项目、路由和查询代次隔离。

- 候选与精确已选项各自读取并明确呈现加载、失败、失效和搜索结果。错误提示放在控件外，关闭下拉后仍可重试。失败缓存不能成为新选择的依据；统一项目刷新覆盖两组读取，刷新等待期间也不沿用旧候选。
- 已选记录仍在读取时标为“待核对”，不提前宣称已失效。保留值的移除动作使用明确的通用名称，读取失败或记录失效后仍可操作。
- 每页必须属于同项目、同实体种类和同查询代次，引用 ID 与实际实体 ID 一致。没有代次参数时，页与已选项仍按同一实际代次关联；当前明确无可用代次时不开放正式候选。
- 传入的成员/实体标签只帮助显示已选值，不作为可写权限。人员与智能体负责人保留名称、类型及稳定 ID；工具和已停用身份不可新选。服务端仍是权限、成员归属与最终写入的权威。
- 明确标记的当前拆解草稿可互设前置关系，取消选择的任务不可新关联。预览生成的本地 key 不误送到正式 Task 查询；原有正式任务仍从有界分页读取。失败时可通过明确的逐项按钮移除不可用的多选关联；单选有明确清空选项时也提供移除。失效项仍禁止添加，不能依赖禁用标签的关闭交互，不能任意新增未知 ID。
- 重新读取同时更换候选/精确读取身份，从第一页开始，保留当前值和搜索，避免反复沿用失效分页游标。搜索可直接清空，本地草稿选项按文本/ID 过滤。
- 会话、项目、实际路由、实体种类和代次决定控件身份；变化时重置搜索/分页。旧回调在渲染前后的范围变化、禁用或读取失败后不能绕过当前候选规则。
- 无账号/项目时明确提示当前范围不可用；查询索引无有效代次时停止正式读取并提示恢复索引，不显示无限加载或无效重试。未指定固定代次的实时读取和明确无代次是不同状态。
- 需求列表/看板中的空负责人筛选明确表示“全部负责人”，编辑中的空负责人仍表示“未分配”，集中编辑的保持/清空选项继续保持原有语义。只读筛选明确允许查找仍持有需求的停用人员/智能体，并标明已停用；新分配继续只接受已启用人员/智能体，工具不成为负责人。
- 沿用现有组件与主题，提示可换行、窄屏工具栏可折行，状态通过可访问关联和实时区域呈现。
