# 正式设计库与设计采用交互

当前阶段按正式 SQL 文档及不可变修订实现。文档编辑、保存修订、恢复修订和归档进入现有交付命令/CAS/原请求回放；需求明确采用后写入正式需求产物，关联任务读取固定的设计上下文。新文档 head 不自动替换已采用原件。具体 DTO、三个设计槽位及 impact preview 以正式后端合同为准。

## 文档库

沿用紧凑工作台，主区域按“列表 → 保存的内容 → 历史修订”排列。列表一页有界查询，默认只读预览，选中文档与修订的直链保持项目及返回位置。新建和新增修订分别打开专用表单，当前保存内容不会被未保存草稿替换。完整原件身份、摘要和请求依据放入折叠明细。

创建、修改和归档均在提交前核对。首次当前读取失败、403、归档状态或无写入权限时保留可读事实与草稿，明确限制，禁止新的提交。冲突保留原输入并显示当前正式依据，明确重新核对后才能生成新的请求。未知结果只恢复原正文/版本/key；当前 GET 不是回执。已知 ACK 清理失败只完成本地确认，不重复写入。

## 需求采用

需求详情内显示当前有效设计集及空缺，提供一个“采用已保存设计”入口。从文档库进入时预选固定保存修订；从需求进入时已固定目标需求，避免再次填写需求ID。选择后精确读保存内容，不用粘贴全文或手填来源名称。

确认页同时展示将采用的保存修订、需求当前依据、当前设计集和完整影响预览。影响不完整、受限或读取失败时不能确认；不能把一页的任务当成完整影响。用户明确采用，随后显示实际新增原件及“查看受影响任务”下一步。旧设计关系及旧执行保持真实历史，不给正在运行的执行替换设计上下文。

## 任务依据

TaskDetail 的设计依据区显示三个正式槽位中的固定设计标题、保存修订和采用来源，提供查看原件的精确链接。关联任务继承需求正式设计集，自身采用覆盖同槽位继承；独立任务也已接入相同的正式采用、完整影响预览与原请求恢复流程，无需另建需求或复制描述。清除自身采用通过同一影响预览确认：关联任务明确展示清除后恢复的需求继承，独立任务明确展示该槽位清空后的生效结果。

执行计划的预览、保存和实际派发上下文应引用同一固定设计。这里只呈现已保存的事实，不把设计采用标为功能完成、测试通过或仓库已接通。项目资源若作为上下文仍明确是已选择的资源参考，实际执行能力由运行目标校验。

## 四态

| 状态 | 主呈现 | 主要操作 |
| --- | --- | --- |
| 未采用或准备选择 | 当前对象、设计槽位、已保存版本与来源；缺少资料给出具体引导 | 选择已保存设计 |
| 核对与确认 | 需求/任务当前依据、精确设计修订、当前设计集差异及完整影响 | 确认采用 |
| 已采用 | 实际保存原件、固定设计上下文、采用者及下一步 | 查看任务并计划执行 |
| 变化、受限或结果未知 | 范围变化与原请求未知分别解释；保留原文与可恢复凭据 | 重新核对当前依据，或恢复同一请求 |

窄屏纵向排列来源和当前对象，正文预览可折叠；所有选择、确认和恢复入口须可键盘操作。加载、空态、读取失败、403及新版本提示分别呈现。已保存旧修订始终按原身份打开，不能悄悄选择最新版本。

本阶段测试定义先补齐，受当前验证窗口约束暂不运行 Node、应用、测试收集、类型检查、构建或浏览器；也不安装、上传或调用外部设计服务。源码与交互落地不等于运行验证完成。
