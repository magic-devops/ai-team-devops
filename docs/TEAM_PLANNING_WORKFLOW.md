# 项目、团队与需求任务分配的衔接

任务 `T-team-planning-workflow`，基线 `d42e4c41d776a2707e5c96785bdc6160d8ae3f06`。沿用已确认的紧凑工作台及正式交付接口，补现有流程中的具体缺口。

- 从交付团队管理项目人员时明确携带当前项目，人员管理页读取该项目；无项目或项目不可访问时要求明确选择，不自动跳到列表第一个项目。可返回同一项目团队。
- 项目页与组织页的正式人员入口统一复用同一管理器；项目页停止调用重复的人员编辑和写入逻辑，仅保留项目总览所需的只读成员数据。角色选项须实际读取成功，失败不生成本地默认角色继续写入。
- 选择器支持搜索，切换项目清空原候选。加载、读取失败和不可访问分别呈现；读取失败不使用缓存成员继续操作，也不显示“暂无成员”。成员角色、任务负责人与 Agent 运行配置仍分别由各自权威接口管理。
- 人员写操作固定点击时的项目及输入，使用同步互斥防止同一帧重复添加、更新或移除；提交期间禁用项目选择。原页面回调、登录身份变化和不匹配的当前地址不能对另一个项目发起写入。完成后刷新原项目的成员、候选和正式交付查询；浏览地址已变化时再同步新项目。
- 所有写回调读取最新成员身份、候选、角色和当前候选草稿，而非使用旧界面闭包里的缓存；相关读取失败、进行中或没有权威选项时，实际提交门禁与禁用状态一致。
- 团队登记页仅展示同项目、同查询代次的成功读取。成员详情按稳定身份精确匹配。加载中有骨架，读取失败保留重试；任务读取失败不显示“尚无分配任务”，不展示被拒绝的缓存任务。切换成员或身份后，旧的任务、日历和配置回调失效。
- 成员读取失败或已移除时，原运行绑定请求的耐久恢复宿主仍可按原项目、原成员身份重试/核对；新配置继续要求合法成员和正式权限。恢复宿主的活动判断不依赖成员当前仍存在。
- 拆解弹窗显示所属项目和固定需求；集中分配只修改选中任务草稿。默认补未分配项，显式勾选才替换已有负责人；另有明确清空动作。沿用人员/智能体的稳定身份选择器，工具不成为负责人。分配不等于实际派发执行，也不创建新的任务模型。
- 选中任务显示已分配/待分配数量；标题、日期、验收和依赖问题定位到任务卡片。全局循环和空选择仍按原门禁提示。批量负责人、编辑、生成与创建共用原忙碌/未知结果保护；当前项目写权限消失时禁用修改。
- 最终保存继续使用原 `tasks.plan` 的固定版本、需求依据、原请求身份、服务端成员校验和原子创建。网络结果未知时保留原请求重试，禁止新分配替换待恢复内容。

## 已编写但未执行的行为定义

纯草稿分配覆盖只补空项、显式覆盖、清空、未选项不变及最终提交内容。真实消费者定义覆盖拆解弹窗批量动作到正式命令、写权限变化后旧回调阻断；团队加载/拒绝/缓存抑制、精确成员与代次、缺失成员的恢复宿主、旧成员回调；项目页实际入口到共用管理器、人员管理直链、无项目不自动选择、切换清空候选、固定项目写入、同帧互斥、角色读取失败、卸载/异路由及身份变更。
