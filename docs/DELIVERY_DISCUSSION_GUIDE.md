# 需求、任务与问题讨论

项目交付工作台的“讨论”入口汇总当前项目讨论。需求详情的讨论页签，以及任务、问题详情的讨论区，都指向同一组真实记录。列表按需分页，深链可以直接打开窗口以外的线程、消息与修订。

## 澄清与形成结论

1. 在具体需求、任务或问题下新建讨论，填写主题和正文。引用正文、验收条目或可访问的执行摘要时，先读取服务器上的准确字段，再选择引用。
2. 成员可以回复；作者可以编辑自己的消息。编辑保存新修订，撤回保留占位与原历史。具有配置权限的成员可以撤回其他人的消息，但不能改写其正文。
3. 选择一条消息的当前修订作为结论。新回复、编辑或撤回该结论会重新打开讨论。归档保留历史，恢复后重新进入待讨论状态。

发言人来自实际登录账户。登记的智能体与开发工具仍是团队责任资源，用户引用执行摘要时显示真实用户及原运行来源，不冒充智能体自动发言。

## 关联已有工作

“关联已有对象”只登记固定结论与现有需求、任务或问题之间的关系。选择准确目标并确认后，双方来源记录可以相互跳转。它不会改变目标的业务定义、进度或验收结果。

来源卡片区分“仅关联”和“已采用”，保留采用时的正文、作者、消息修订和实际结果对象。后来讨论有新回复或新结论时，卡片会提示来源发生变化，原快照继续保留。受限运行引用按当前权限隐藏；原消息正文与服务器执行引用分别显示。

## 明确采用为业务修改

采用结论先进入原业务编辑器，检查预填内容、影响与当前依据，再明确保存。讨论解决本身不会完成任务、通过质量验收或启动执行。

| 入口 | 保存后的实际结果 |
| --- | --- |
| 采用到需求 | 原需求变更预览与保存；沿用影响确认与版本检查 |
| 调整任务 | 修改原任务；定义变化继续使已有验收按原规则失效 |
| 形成任务草稿 | 检查当前所属需求，编辑并确认计划后创建真实任务；来源对应每个新任务 |
| 问题转需求 | 沿原唯一来源需求规则创建或打开需求；结论可预填验收标准，原问题不自动关闭 |
| 诊断采纳 | 沿原诊断审核、证据权限与采纳规则保存，同时保留诊断和讨论两种来源 |

查看已有采用记录后优先打开实际结果，避免把再次点击误当为新任务请求。任务后来转属时，讨论仍属于原任务 ID；打开任务会重新读取其当前归属。目标已删除或无法访问时留在当前页显示错误，不跳到其他对象。

## 草稿、冲突与恢复

- 草稿按登录身份、会话、项目、对象、线程及编辑模式隔离。发送期间继续输入的内容会保留；缺少可靠本地身份信息时只保存在当前内存。
- 网络异常或服务端错误导致结果未知时，使用“恢复原请求”确认同一次提交。它保留原输入和请求标识，不再次创建任务或来源。
- 版本或分页冲突时保留草稿，显式重新读取首屏或最新依据。读取最新内容不会自动覆盖用户文本；采用新依据需要明确操作。
- 权限撤回、对象缺失和归档状态分别提示。切换项目或会话后的迟到响应不能清除当前草稿或导航到旧对象。

默认每页 20 条，最多 50 条；消息编辑历史固定读取时的修订上界。普通讨论只刷新讨论和来源查询，业务保存继续刷新对应业务详情。正文按纯文本显示，中英日文案、键盘标签、窄屏换行沿用现有界面体系。
