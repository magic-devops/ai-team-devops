## 统一约束

1. 所有项目业务数据读取先验证有效身份、明确的 `X-Project-Id`、真实项目与实际项目读取权限。JWT 与已验证 HMAC/API Key 使用同一项目授权规则。
2. 无身份返回 401，无明确项目返回 400，项目不存在返回 404，无权访问返回 403。不能通过环境默认项目、请求参数、匿名下载或调用另一个路由函数绕过授权。
3. 项目只读请求不得初始化项目、业务状态或图谱。缺失项目和权限错误不能被吞成空列表、零计数或成功的 degraded 汇总。真实有效空项目正常返回明确的空结果。
4. 复用既有异步 `business_access` 授权与范围绑定链，保证同步处理函数运行前范围已建立，处理结束后复位。middleware 的项目解析不作为身份门禁；项目数据路径必须禁止自动 provision。
5. 普通 Python 函数调用不会执行 FastAPI `Depends`。组合接口的外层真实 HTTP 入口必须授权，不能依赖其调用的任务/研发函数所在 router 的保护。纯全局目录与项目业务汇总分开标明授权范围。
6. 具有持久化能力的动作按实际项目写权限执行，归档项目只读。纯计算 POST 可使用读取权限，但其实现必须不保存领域状态。原数据导入的额外角色限制保留，并使用已授权项目的租户范围。

## 接口处理

| 类别 | 目标行为 |
|---|---|
| dashboard、analytics、关键词/语义搜索 | 项目读取依赖；不使用无鉴权的环境项目；无效项目不建项目 |
| data-exchange summary/charts/jobs/export | 项目读取依赖；导出移除公开/前缀跳过；读取和下载同一真实项目 |
| data-exchange preview | 明确项目的纯读取/输入计算，不保存记录 |
| data-exchange export-job/import | 实际项目写权限；导入保留额外角色限制；actor 与目标租户来自授权结果 |
| knowledge-graph summary/entities/edges/lineage/query | 项目读取；query 不隐式保存构建结果；未构建时明确提示并引导显式构建 |
| knowledge-graph build/profile merge | 实际项目写权限和既有归档/文件写守卫 |
| interaction-ops、governance-tasks 等组合接口 | 外层按真实读写行为授权，阻止借普通函数调用绕过依赖；授权错误不被伪装为空数据 |

`/api/v1/dashboard/hub`、`/summary`、`/charts` 是已有认证的全可见项目组合首页，不等同于 workspace 的精确 `/api/v1/dashboard`；保留组合首页语义，不把它误纳入当前项目门禁。首批页面测试使用真实的当前项目 AnalyticsOverview 消费者。

最终端点清单以真实调用链和回归证据为准，不能为了覆盖字符串而给所有全局目录强加项目选择，或用整个 `/api/v1` 的宽泛规则破坏登录及项目选择启动流程。

后续精确审查已确认workspace的`/specs*`使用共享`sop_dir()`，不是项目私有资产；本阶段没有给它强加项目选择，也没有修复其既有共享写权限问题。其他待完成项包括workspace可选向量源的项目局部绑定、global dashboard携带失效项目头时的零初始化行为，以及组合入口的typed预览/真实写权限分流。它们不得由首批20项回归的结果代替验收。

## 交互

- 复用当前 session provider、项目选择和上下文提示。无登录或无项目时不挂载项目业务查询子树，仍可使用导航、登录和项目管理。
- 当前读取返回 403/404 时，先隐藏已失效的业务正文，再展示可操作的项目选择/重试。不能继续显示 query cache 中的旧正文。
- 现有 `SessionQueryProvider` 已清理缓存并重挂观察者，不能只凭全局 query key 就宣称存在跨项目泄漏；通过实际消费回调验证切换行为。
- 导出使用既有认证和 session 绑定的请求链，显式携带原项目头。禁止裸链接绕过认证、URL 携带 token，或在旧回调中顺带下载新项目。
- 请求开始前、开始消费响应正文前、正文消费后和创建下载前检查原 session/project 是否仍有效。切换后丢弃原请求结果，并给出重新操作提示。
- 保留现有历史回看、未知提交结果恢复及离开保护；共享项目提示不能把仍有原请求可恢复的外层宿主卸载。
