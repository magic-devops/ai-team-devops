# 使用团队开发工具执行任务

当前为源码阶段，尚未完成实际运行与界面验证。

1. 在项目“团队”中登记开发工具，进入工具详情的“运行配置关联”。有项目配置权限并可读取运行工作区的人员可以关联现有配置的固定版本。
2. 明确选择工作区和配置。核对实际提供方与版本，再保存关联。名称相同的工具仍按独立成员身份记录。
3. 在任务详情选择派发资源。工具的“平台执行”项显示真实配置、版本及可选位置；未关联或能力不足时会显示原因。需要人工在外部工具完成工作时，可选择其“外部协作”项。
4. 继续核对执行位置、测试和计划，预览后再明确派发。执行结果、测试证据和人工验收沿用任务中的既有流程。

工具登记的名称不会自动安装或连接相应产品。实际平台执行使用所关联配置的提供方；关联有效不代表外部工具已认证接通。

停用工具后关联会解除。恢复启用需要重新关联并制定新的派发计划。旧的未交接意图不能继续使用；已经交接的运行仍保留原快照，需要停止时使用运行控制操作。

SDK 读取使用 `delivery_team_runtime_bindings()`，保存使用既有 `delivery_command()`。CLI 使用 `delivery team-runtime --json` 读取，使用 `delivery command --file <原请求文件>` 保存。重试保留原 expected_version、完整 payload 和 idempotency_key；并发冲突须明确核对后另建操作，不自动修改原文件。

关联编辑器的同一授权标签页会话原请求恢复见 `docs/BINDING_OPERATION_RECOVERY_GUIDE.md`。结果未知时使用原件恢复，确认回执后应用并刷新；跨账号或新标签页恢复不在当前范围。实际运行与界面验证仍待执行。
