# 发布源码关联草稿与操作反馈

任务 `T-release-source-drafts`，基线 `fac2b1ecb33b8692ebea1b39833db06b747ede20`。

源码准备原先只把填写保存在抽屉状态中，关闭后即丢失；按钮因缺少完整 SHA 或说明而禁用时，用户也缺少具体提示。本阶段延续既定紧凑工作台，补齐同一登录会话、同一标签页的草稿恢复和逐项填写反馈，不增加新的发布审批步骤。

## 交互

- 填写和当前任务位置暂存至 `sessionStorage`，可关闭后重新打开。草稿键隔离租户、用户、登录修订、项目、完整范围依据及信任配置代次；完整记录还逐一匹配仓库、工作流、显式选择及实际包含任务。
- 恢复只带回填写和位置，不保留生成包、签名、请求身份或已验证状态。恢复后必须再次调用已有只读准备接口，从当前验收重新核对。
- 不自动推断提交，不默认非代码。逐项说明缺少关系类型、完整 SHA、格式一致性或具体理由；说明改为多行输入。服务端仅对关联说明允许正常换行和制表，身份及 CI 元数据不放宽；非法控制字符与无效 Unicode 仍拒绝。
- 无法暂存时仍可继续填写，但明确提示。关闭、Escape、遮罩、路由切换和刷新都保护当前未保留输入；确认放弃只关闭编辑器，已保存旧稿保留。该确认只在可能丢失输入时出现。
- 清空全部填写和生成结果需明确确认，仅删除当前精确范围的草稿。损坏或身份不匹配的记录不自动覆盖；用户可明确清空后重新填写。
- 读取后修改前比较原始存储值。另一个编辑器已写入的新稿不被旧实例覆盖或清空。草稿最多 1 MiB，超限或存储配额不足不虚报保存成功。
- 项目/会话切换时，宿主不把旧项目捕获的质量内容显示成新项目的编辑器；编辑器自身也订阅身份变化并隐藏旧内容。当前导入权限丢失时禁止改内容、清空和生成，仍可查看草稿。
- 宿主筛选和刷新在改变内部路由状态前先询问编辑器离开守卫；全局离开守卫处理外部导航和刷新。未保存状态不会被登记为未知写操作，因此不妨碍继续修正填写或重新暂存。

## 验证边界

新增存储合同和真实组件回调的行为定义：冷启动恢复、无令牌/生成包持久化、登录/项目/范围/策略隔离、错误原件保留、同槽竞争、限额/多字节、清空确认、关闭及真实离开守卫、只读和迟到会话。本阶段按用户要求未运行测试、应用、类型检查、构建、格式化或浏览器。源码审查不代表运行或可视化验收。恢复窗口后先验证固定提交，并在实际窄屏、键盘及失败状态中复核。

这只补发布准备体验，完整全流程目标继续推进。实际适配器握手、自动运维编排及生产验证不因草稿实现而完成。
