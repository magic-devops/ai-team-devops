# 任务派发与退回修改

本指南描述阶段 `T-external-tool-workflow` 的代码设计。当前按用户安排暂缓应用、类型、构建与浏览器验证，尚无实际运行或外部平台接入通过的结论。

## 选择执行方式

在任务详情进入统一派发，先核对项目、任务要求和验收条件。平台智能体使用项目正式团队绑定的工作区、Agent 版本及执行目标，随后进入原计划编辑器核对测试方案、预览并确认。存在多个目标时明确选择；当前能力不可用时根据页面原因补全配置后重新读取。

手工命令继续使用已有原生计划能力；外部协作使用固定工单。外部工具登记名称与工作包下载均不代表进程已经启动。活跃外部工单与原生执行的互斥仍然生效，需要先完成或关闭原交付，不能通过换入口避开。

## 根据退回意见重新派发

从被要求修改的精确报告进入返工派发。页面携带该报告、原摘要和那次退回结论的明确引用，显示退回意见、历史工作要求与报告自报信息。核对当前任务定义后选择执行方式；来源不可读或引用不匹配时先解决页面给出的具体原因，不会自动换一份报告。

原生执行与外部工单均在预览时固定完整反馈，并将同一内容带到工作包或实际 Agent 输入。历史测试只是原报告的自报信息，本次仍需执行本次测试并重新提交验收。该操作不会自动关闭关联问题或沿用旧的通过结论。

外部工单详情和接单前可直接阅读固定任务定义、验收条件、说明及所选反馈；完整工作包下载仍保留。当前任务后来改变时，工单中的固定工作要求仍是原件，应重新核对是否需要新的派发。

## 保存失败与结果未知

保留已有的请求原件恢复流程。确认未完成和结果未知是不同状态：结果未知时重放同一版本、同一请求键和同一正文，不另建一次派发。确定冲突后先读取最新事实，再明确采用新来源和重新预览。当前数据刷新不等于原操作已经确认成功。

## SDK 与 CLI

W 预览及新建请求可携带同一 `feedback_reference`，其内容只能是三个正式引用字段。保存原 JSON 后重试继续使用该文件；客户端不会补版本、补请求键、读最新报告或改写文件。E 预览与入队通过已有原请求接口保留该引用。下载工作包时验证完整包摘要，完整反馈也在这个固定摘要内。

CLI/SDK 此阶段保留既有回执接口，尚未新增完整会话恢复日志或严格操作回执协议。自动执行外部工单、新平台连接及实际运行可用性分别需要后续实现与验证。
