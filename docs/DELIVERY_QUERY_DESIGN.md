# 有界交付查询与精确工作区

基线 `1cec3e6`。任务 `T-delivery-query`。完整研发协作目标继续 active；沿用现有业务实体、六态验收口径、Ant Design 及主题，不保留无用途的重复接口设计。阶段验证后全部 commit，不推送。

## 问题与实测

需求列表的20行分页实际发生在下载整个项目之后；每个业务视图及独立任务详情仍会读取完整 workspace，编辑冲突恢复与写入响应也再次物化所有实体。当前物化重复读取 Task/Requirement/Issue 和验证 Context，每条需求再遍历所有任务。进度与排期已有独立范围接口，但父请求使它们仍承担完整下载。

隔离 SQLite 夹具以一次 bulk 事务创建10000需求及10000任务，现有 workspace 实际计算117.53秒，JSON编码结果60,499,946字节。此为本地函数/SQL夹具观测，不是HTTP、生产压测或外推。方法、身份查询开销、原始结果与源码依据留在本阶段证据中。

## 架构决定

采用同一业务事务维护的可查询派生事实索引，供列表、筛选、总量和全项目指标读取；精确详情另读取当前对象正文和必要证明。索引没有创建/编辑任务或需求的业务接口，不保存需求正文、任务正文、运行日志或第二套业务归属。Project / Requirement / Task / Sprint / DeliveryWorkspace 仍是唯一业务来源。

仅对完整查询结果加LIMIT不能修复源读取成本。先对raw状态分页再计算有效状态会漏项和错误计数；依赖及集体验收的证明闭包最坏可达全项目。因此列表使用由相同事实计算器得出的六态索引，不能用原始completed、近似计数或当前页替代完整语义。

先将计算器按需求预分组任务、问题、最新执行和审核，复用一个最终有效状态及VerificationContext输出给物化、历史观测与索引。保留集体验收的独立证明路径，禁止把它改成all(task.verified)而产生循环。进度fact basis与真实task basis保持区别。显式全workspace导出继续作为工具能力存在；first-party UI不以它轮询或恢复，不保留永久v2兼容层。

## 一致性、授权与索引生命周期

业务写入继续使用项目CAS、任务/需求basis、预览依据及原幂等身份。查询代次独立于业务版本、观测序号和运行心跳，只用于识别本次查询所依据的事实和筛选元数据；不得当作审核或写入授权。相关正文、归属、依赖、身份、评审、发布、删除、排序/筛选字段改变必须使代次变化，纯技术日志不伪造业务进度。

派生事实在同一SQL事务内原子维护。必须覆盖ORM与Core、旧/新项目作用域、删除、身份与评审人权限、归档/恢复、保存点及回滚；不能因观测去重提前return或lifecycle跳过而漏维护。现有Project→Workspace锁序保持。读取每次重新校验当前项目权限；执行/部署来源仍按当前运行空间权限读取，游标不授予权限。

已有项目缺索引时明确rebuild_required，GET不初始化、不写历史、不回退整包。提供有实际授权的显式重建，原子发布当前事实，标明计算时间；不补造历史观测、审批或验收。重建中断和重复请求不能留下半套索引。当前可用索引的替换应有明确代次切换，不把失效缓存冒称当前事实。

游标签名绑定租户、项目、当前用户、实体种类、规范筛选、排序、页大小、代次与位置。每次查询固定当前事实范围；代次改变返回结构化409，保留筛选并明确重新开始。可变业务实体不能沿用不可变历史上界就声称翻页不会漏重。count、facet与page须处于同一事实代次；再次读取代次必须实际查询，不能读ORM identity map旧值。

## 读取与命令合同

- 轻量context只负责当前项目、权限、版本/查询状态和真实全范围指标；不返回业务实体或运行正文集合。
- 需求与任务列表由SQL进行筛选、准确count和分页，行只含需要展示的摘要。看板各阶段独立游标，列总量来自服务端facet。
- 需求与任务详情按精确ID读取，页面外实体正常打开；正文、局部计划、有效状态、正确basis及关联引用分别表达。关联任务、审核、历史、执行和日志按自身合同加载，不借详情下载全项目。
- 成员、里程碑、资源与执行目录使用有界引用查询；已选ID可精确解析，不因不在当前候选页被当作无效。成员分配数、里程碑进度由完整服务端事实计算。
- 问题列表使用独立有界查询，保持现有精确问题/诊断详情；执行选择同样支持精确读取和当前权限。
- flow、task_details和指定execution在SQL中按路径投影，不能先解码整个workspace.data再切片。精确详情读取的历史内容范围与用途必须明确。
- commands统一返回typed ack：精确项目/动作、原始resource及业务结果/关联引用、实际应用版本、当前版本、重放标记。首次与重放均不物化workspace；原结果由不可变事件/回执恢复，不按当前实体猜测。传输偏好不影响幂等请求身份。基线创建返回原baseline_id，问题回流返回原关联需求ID。

最终字段与路由以同时冻结的真实后端合同为准，并同步SDK、CLI、OpenAPI和所有first-party调用方。

## 四个关键界面

1. **需求列表与阶段看板。** 搜索、阶段、负责人、排序和游标进入URL，当前需求目录20条/页；请求进行中、错误、无匹配、全局为空分别表达。列头来自完整facet，页面内已载入行不用于全项目百分比。游标失效保留筛选并明确刷新，不静默拼接两代次。
2. **精确需求详情。** 打开任意ID独立加载正文与流程；关联任务分页，活动/版本保持已有精确服务。读取失败可在详情内重试，未加载不报删除。返回恢复列表或看板分支、筛选、游标和焦点。
3. **任务详情与编辑。** 独立入口与需求内任务使用相同精确详情。负责人和依赖候选远程查询，已选对象不随候选页消失。固定编辑快照、CAS冲突明确采用、未知结果原key重试及父退出保护保持；不把局部数组交给全图合法性校验。
4. **专属视图与提交反馈。** 进度、排期、团队、问题、质量和发布进入时不触发父完整workspace。服务端范围指标与容量语义保持完整。保存ack后只刷新相关上下文、页或精确对象；不关掉未完成请求，不回退完整导出，不从响应数组猜新ID。

沿用三语、现主题、键盘与390px单列/独立详情。当前浏览器协议访问及12ui安装/上传曾被自动审批拒绝，继续遵守限制，不重试或绕过；交互测试、HTTP与类型构建不能冒称当前实机视觉已验证。
