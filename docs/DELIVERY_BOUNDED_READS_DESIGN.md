# 质量与版本目录的有界读取

任务：T-bounded-delivery。基线：8a4201815c5138517b4b26367095c73169dcff29。

## 问题与范围

已有审计复现：只选一个独立任务仍读取整个项目的任务、需求和工作区；质量和版本两个入口每五秒同时读取质量全集及所有 CI、候选、旧手工记录。列表提前携带验收证明、签名声明、候选完整快照，用户展开详情之前就付出这些成本。

本阶段完成质量目录、范围质量、CI 目录与详情、候选目录与详情，以及 Web/SDK/CLI 使用链。人工评审历史、进度基线、需求影响历史和 Issue 反向来源链仍为后续明确范围。

## 数据边界

- 列表从当前写事务生成的查询投影读取，默认 20、最多 100 条，完整过滤计数与显示页分开。游标绑定项目、租户、读者、过滤、页大小及查询代次；代次变化拒绝续页，不混合新旧页。
- `GET /quality/catalogue` 返回需求和独立任务的小摘要；筛选在服务器执行。摘要不携带验收标准、全部任务 ID、证明正文或 CI 声明。
- `GET /quality` 只检查明确选中的需求及独立任务。需求必须包含其全部任务；证明闭包必须包含必要前驱、其父需求全部兄弟任务、当前身份、问题、最新评审与执行证据。最多 500 个任务，超出返回 413 `quality_scope_too_large`，不能以截断数据宣布通过。
- 范围验收与写命令共享原有验收算法；相同数据的 `scope_basis` 必须与完整 canonical 验算相等。GET 不补投影、不创建工作区、不写库。缺失或失效投影明确要求有权限者重建。
- `GET /releases` 仅返回策略与权限上下文；`GET /release-pages?kind=candidate|evidence|legacy` 三类目录独立分页。目录陈述已记录的决定/结果，不将目录摘要当作当前可批准凭据。
- `GET /releases/{id}` 与 `GET /release-evidence/{id}` 才读取选中原件及其当前证明。使用工作区 JSON 精确路径和投影位置，不能装载整个工作区。
- 已存在原件不能因当前范围增长超出同步预算而失去查看、拒绝或撤回入口。此时返回明确“当前证明未完成”，不能批准或声称有效，也不能把检查预算不足锁存为永久业务失效；完整 `GET /quality` 仍返回 413。
- 评审依据固定候选原文、登记决定与评审历史，派生的当前有效性或检查预算不属于这份原件。批准命令仍在项目锁内完整核验当前范围、CI、策略及权限；拒绝/撤回可控制已选原件，不依赖是否能在同步详情预算内重新证明全部工作。
- 完整候选创建、签名验证、防回退、审批、部署门禁继续在写入时完整验证。原版本、原预览依据、原幂等键及未知结果恢复规则保持有效。

## 交互

质量页只主动加载质量目录及小上下文；版本页只主动加载候选目录及小上下文。CI 和历史目录由用户展开，原文/完整质量由用户打开详情后读取。筛选、下一页、返回上页、选中范围和关闭抽屉各自清晰，跨页保留明确选择。目录展示完整总数与当前页覆盖，失败或代次变化不能显示空页成功，也不能继续使用失效读数写入。

候选编辑器通过分页 CI 选择器选择明确证据；证据详情单独读取。原意图遇到未知结果、项目/会话变化时不得偷偷生成新键或用另一身份提交。三语文案沿用现有设计系统与移动布局。
