# 固定设计版本与实际交付

本阶段连接项目设计库、需求或任务的明确采用，以及实际智能体任务输入。当前为源码阶段，运行、类型、构建、浏览器和真实供应商版本验证按用户要求后置；不能据此宣布完整链路已稳定通过。

## 使用顺序

1. 在项目设计库创建或导入 Markdown，编辑后保存为新版本。列表只读摘要，查看原文时指定确切版本。
2. 从需求或任务的设计区选择产品需求、交互原型或架构设计。查看当前采用、替换后的有效版本和完整影响，再明确确认采用。任务可以覆盖需求同类设计；清除任务选择时会显示继承后的结果。
3. 任务派发固定当时的设计版本、摘要与完整正文。设计库继续编辑不会自动更改已采用版本；替换采用需要再次确认影响。
4. AI 完善只产生建议。检查完整建议、修改后保存为新设计版本，再决定是否采用。生成成功不代表已保存、已采用或已通过人工验收。
5. 回执丢失时恢复同一个操作，保留原内容、版本和请求身份。已受理的生成请求若仍在处理中，不会自动再次调用模型。

旧 `.ai-memory/tech_design` 中的人工原件保留，不自动扫描、迁移或删除。需要使用的内容由用户明确导入正式项目设计库；没有保留旧文件 API 的隐式全局写入设计。

## 正式业务边界

设计原件使用项目 SQL 文档头、不可变版本、不可变采用记录。保存通过文档版本及原版本摘要比较；恢复旧版本会追加新版本，归档保留引用原件。需求与任务仍使用原有业务身份，没有第二套任务或需求。

采用或清除使用原项目版本、目标依据、当前设计集合依据和完整影响预览依据。服务端在项目锁内复核全部影响，使用既有进度、任务验收和发布校验机制。设计本身不是批准事实。任务独立完成、报告的检查结果、人工验收与实际部署继续分别记录。

三类设计各最多 64 KiB UTF-8，合计最多 192 KiB。任务快照保存固定版本元数据，原生派发私有原件装入已核对摘要的完整正文。缺失、变化、损坏或超过预算时明确拒绝，不静默截短、不回退到当前文档头。工作区显示执行目录；没有仓库或提交证明时不称作已验证 Git 来源。

## SDK 与 CLI

SDK `design_documents`、`design_document`、`design_revisions`、`design_revision`、`design_compare` 读取明确原件；`delivery_designs` 和 `delivery_design_adoption_preview` 读取采用与影响；`design_command` 发送完整原业务命令；`design_generate_preview` 与 `design_preview` 请求或恢复同一建议。

CLI 在 `delivery` 组提供 `designs`、`design`、`design-revisions`、`design-revision`、`design-compare`、`design-current`、`design-adoption-preview`、`design-command`、`design-generate`、`design-preview`。写操作从明确原 JSON 文件读取，不自动查询替换依据或生成新请求身份。文件会校验重复键、非有限数、完整 UTF-8 和整体大小，发送失败不改写原文件。

## 执行输入

完整任务与设计通过执行器 stdin 传递，避免 Windows 命令行长度限制。执行器核对请求摘要并回传摘要，Core 核验后才接受结果；仍保留停止请求、子进程树停止、等待结束与输出 EOF 的原有证据。

Codex 的完整 stdin prompt 方式来自[官方非交互文档](https://learn.chatgpt.com/docs/non-interactive-mode)。Claude 使用固定短指令加完整 stdin，依据[官方程序化运行文档](https://code.claude.com/docs/en/headless)。官方说明只支持协议选择，不证明当前机器的供应商认证、安装版本或真实执行已验证。

OpenCode 保留[官方 CLI 文档](https://opencode.ai/docs/cli/)中已明确的完整短消息参数方式，完整输入限制为 8 KiB UTF-8，且实际 Windows 参数转义后的长度另行核对。较长正文的 stdin 方式尚无已核实的当前接入协议证据，因此在派发前明确阻止并说明原因，不截短、不重复传入。当前官方仓库已有 CLI 重构，后续应结合实际安装版本验证或实现明确适配，再开放长输入能力。
