# 业务任务与执行链路设计（2026-10-16）

沿用已确认的紧凑工作台与本地设计验证流程，执行信息嵌入需求详情的任务区域，不另建一套业务任务列表。

## 四个关键界面

1. **派发预览**：任务卡片内进入表单；选择已有执行工作区、版本固定的智能体或命令计划，以及可选远程设备。展示需求修订和验收条件。明确“保存派发计划”只持久化意图，随后同步生成运行、由用户启动。未配置执行权限时展示原因与已有工作区入口；提交失败保留草稿。
2. **运行进度**：任务下展示独立执行卡片，包含执行状态、已成功节点比例、观测时间与运行编号。运行成功显示“待审查”，任务完成比例保持不变。刷新证据、启动、取消分别可操作，失败反馈紧邻操作。所有历史执行保留，最新执行优先展示。
3. **测试与验收**：展开节点证据显示退出码及日志；显式标记测试节点。显示原始需求快照和验收条件，变更后醒目标记“需求或任务已变化”。验收操作必须填写意见并固定当前运行版本；仅成功运行且证据齐全才能通过。Agent 输出不自动冒充测试报告。
4. **问题回流**：失败运行创建关联任务的问题，重复同步不重复创建；在原问题反馈视图可继续转需求。原运行、原需求修订和失败问题互相可追溯，转需求不自动解决问题。

## 一致性与边界

- Manager 管理业务任务、需求和验收；已有运行模块管理进程、设备、日志、节点证据。运行模块中的任务为固定快照执行信封。
- 先提交派发意图，再进行可重试跨存储同步；运行模块使用稳定的原始派发人和意图 ID 去重。
- 同步时重新验证项目、工作区和执行权限，不扩大原运行模块的授权范围。
- 需求/任务变更不得沿用旧验收；通用任务更新入口不得直接完成已纳管任务。
- CLI/SDK 使用同一版本与幂等命令接口。计划、运行、审查三个状态分开显示。
- 尚不宣称所有厂商均已实机接入；复用现有 Codex/Claude/OpenCode 适配器，运行设备配置与授权仍沿用现有控制面。
