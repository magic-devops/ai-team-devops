# 任务详情阅读与处理导航

任务：T-task-detail-navigation。沿用用户确认的紧凑协作工作台方向，本轮只调整当前任务详情的阅读组织，不增加业务状态、执行渠道或写入入口。

## 已发现的问题

任务详情先显示外部工单，随后依次展示任务、平台执行、验收条件、讨论、计划、设计、交付报告和人工审核。区域较长，平台执行与外部执行的信息来源不同，用户需要反复滚动寻找实际处理入口。记录状态与服务端有效交付状态必须继续区分。

## 交互方案

详情顶部提供紧凑且可换行的区域目录：任务、平台执行、外部工单、设计依据、交付验收、计划依赖、讨论。目录只在当前详情根节点内定位，移动键盘焦点且不更改地址、项目、任务身份或待恢复原件。所有区域继续挂载、可见；不使用会卸载编辑器的标签页或折叠恢复入口。

顶部摘要分别显示记录状态和有效交付状态，只依据服务端字段给出“查看处理区域”的建议。有效验收完成必须同时满足 verified 与 verified_completed；记录完成不能推出验收通过。原生运行的审核与问题留在平台执行区域；依赖阻塞定位计划依赖；外部报告和人工审核定位交付验收。未读取到任务事实时，不推断当前进度或可写能力，仍保留独立恢复区域。

没有原生执行 ID 不表示存在外部工单，也可能是人工工作。因此仅对明确的原生运行、依赖阻塞或待验收/记录完成事实提供建议，其余不推断下一步。目录保留显式入口。任务读取失败仅禁用依赖该读取的派发等入口；独立报告、设计与恢复区域继续按其自己的读取、权限和原件合同处理。

编辑或待恢复操作期间，原宿主会固定任务快照。摘要显式标明固定快照与快照交付状态，不据此声称当前条件已验收，也不显示下一步建议。处理完草稿或原操作并刷新后，再根据当前读取表达状态；不为刷新摘要而绕开冻结保护。

目录在窄屏换行，焦点边界清楚，区域预留滚动边距，减少动态效果偏好时直接定位。沿用项目颜色变量与原有控制器，定位不调用写入或自动派发。

## 验证边界

按用户安排，当前只进行源码阅读、文本结构、哈希和 Git 范围检查。新增行为定义先于实现保存，但尚未运行；类型、构建、真实浏览器滚动/焦点/窄屏与稳定性验证，均等待用户确认验证窗口恢复。目录不代替后端权限、原请求恢复或完整链路验收。
