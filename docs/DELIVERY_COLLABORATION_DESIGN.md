## 数据、授权与写入

沿用唯一 Project / Requirement / Task / Sprint 及 DeliveryWorkspace。活动新增安全、稳定的对象关联；按服务端固定范围筛选后再分页，游标绑定租户、项目、过滤器及固定上界，后来的记录不会插入正在翻阅的历史。详情按精确事件ID读取。活动输出仅白名单字段，不发送原始 input/result/before 或运行命令、凭据、日志正文。导航目标由当前同项目对象与实际权限核验，缺失/无权明确表示，不退回第一项。

需求历史只保存真实新观察的规范内容、basis、修订和观察时间。缺失历史不补造，观察时间不冒称原始修改时间；未记录当时关联的旧事件不按任务当前归属推断历史归属。通用需求写入也应经过同一事务观察机制。活动不声称已消费所有外部存储事件，跨存储执行事实以已明确同步入业务库的内容为界。

需求变更预览读取当前 requirement basis 和项目版本，返回字段前后值及服务端影响摘要。提交绑定 requirement basis、preview basis、项目CAS和原幂等身份，重新核验；预览不写数据，不运行模型或命令。涉及需求内容的改变继续沿用既有修订/验收失效规则；仅管理字段变化不得误称全部交付依据失效。影响必须区分直接关联和下游依赖，现有证据保留只读，不自动改期、重派、重跑或验收。GET不初始化任何记录。

Sprint completed/remaining/completion_rate 使用同一有效验收口径；登记完成单独表达。范围必须保持当前租户、项目及迭代，不能用展示页的分页缩小容量或真实进度聚合。

## 四个关键界面

1. **项目与需求活动。** 在现有概览和需求活动标签内共享紧凑列表，显示动作、目标、操作者、时间、真实关联与影响提示；服务端范围筛选，显式加载更早记录和重新读取最新记录。列表为空只说明当前已记录范围。过滤、选中事件和返回来源进入安全URL；加载、失败及重试均在当前面板展示。
2. **事件详情。** 只读抽屉显示当时事实、已记录字段变化及关联，当前对象可访问才提供打开动作。删除、无权、旧关联未知均保留事件本身及安全返回。真正链接/按钮可键盘操作；关闭恢复触发位置；不能把加载或失败当成对象不存在。
3. **需求变更编辑与预览。** 编辑保留草稿，预览展示字段差异、修订/阶段影响和受影响工作，明确确认才提交。409先读取最新再由用户明确采用并重新预览；读取失败不能采用。未知结果使用原请求身份重试，不新建重复命令；保存完成前不关闭。创建需求保持既有合理流程。
4. **需求历史与影响。** 现有需求详情提供已记录版本列表和精确只读内容，明确当前事实与历史观察，缺失早期内容清楚提示。影响对象进入已有任务、执行、候选、部署或问题界面，并可返回原需求/记录；不新增重复工作台。

390px采用单列卡片、纵向字段差异和不超视口抽屉；长ID/标题可换行，筛选换行，焦点可见；三语使用现有翻译体系。当前浏览器协议访问和12ui安装/上传曾被自动审批拒绝，遵循原限制，不重试或绕过。源码、交互自动测试与真实HTTP不能冒称本阶段实机视觉验证。
