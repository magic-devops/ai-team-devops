# 派发原件与回执恢复

阶段 `T-execution-dispatch-recovery` 起于 `b67f609`；当前由 `T-durable-execution-handoff` 补齐后台交接及观察式同步，详见 `DURABLE_EXECUTION_HANDOFF_DESIGN.md`。按用户要求先完善源码、流程和交互，运行检查等待资源及共享验证窗口。当前设计和回归定义不代表运行通过。

## 用户流程

任务详情集中配置工作区、成员或直接Agent配置、明确执行目标、命令测试及可选审批。预览固定需求/任务依据、目标与配置版本、命令参数边界和测试节点，明确确认后才保存执行意图。保存本身不创建运行，也不代表测试或验收通过。

保存中使用同步锁，旧按钮、取消、字段和策略编辑回调都核对当前操作资格。重新预览或重新读取依据前撤销旧证明；并发拒绝保留草稿，读取新依据、明确采用后重新预览和确认。保存失败不能静默关闭表单。

队列命令的唯一持久宿主位于任务详情，正常编辑器使用同一控制器。恢复时只展示原请求中的项目、任务、工作区、成员关联、目标、固定依据和命令/测试摘要；不把它伪装成服务端已保存的验收快照，也不依赖当前可变目录重建原请求。目标、成员或任务详情读取失败时仍能恢复原件，新命令停用。

同步动作由独立控制器处理，只观察已经存在的外部计划并回写Manager业务事实。计划由已受理原件的后台交接准备，启动进程另需正式授权操作。同步、启动/停止/审批、业务审查互相使用即时锁，避免旧回调在同一时刻发送另一类操作。取消、进程停止、测试结果与人工验收继续分别呈现。

## 原请求与回执

队列以租户、用户、登录代次、项目、任务隔离；同步以同一范围及执行意图隔离。发送前保存原动作、完整正文、原版本和幂等键，不存token。未知结果只能恢复同一原件；当前状态读取不能替代命令回执。

队列和同步只写Manager SQL，首次明确4xx可以结束本次被拒请求，读取新事实后重新采用依据；旧按钮失效。网络结果未知或未知请求的重放再次被拒仍保留原件，不能根据后来的4xx解除未知状态。发送前无法保留原件则不发出请求。旧协议已有的外部副作用与回执缺口仍需要独立对账，不能套用新请求的明确拒绝语义。

正式queue/sync的ACK结果均为`null`，只有一个execution资源引用。queue核对服务端新生成的执行意图ID，不能拿任务ID当执行ID；sync核对指定执行意图。二者均核对项目、动作、原版本及实际ACK结构，不要求不存在的任务/需求引用；成功后主动失效相关业务查询。

回执确认后先清理本地恢复槽，再刷新业务事实。清理失败保持“已确认”，只提供本地清理，不再次POST。浏览器记录上限1,500,000个JS字符，发送前预留8,192字符给有界ACK；这是存储预算，不表示计划一定符合外部执行器的UTF-8大小限制。

## 刷新与恢复宿主

研发工作台在业务context查询之前检查精确URL中的任务或执行身份。发现原件时先固定恢复宿主，直到本地恢复结束才装载业务页面；context初次403、重建提示或迟到GET不会把原件遮掉。独立任务页在详情读取之外保留队列恢复控制器。

执行详情同时识别同步和运行控制原件。若两类均存在，一次只恢复一个，组合未决状态继续保护退出。已知执行身份的任务详情、当前执行、历史执行及历史列表读取失败后，恢复宿主保留在业务事实区域之外；迟到成功读取不会抢走恢复操作。详情关闭动画立即撤销旧回调资格；历史原件恢复不读取当前目录来猜造新目标。损坏或不可读取的原件停止新提交，保留排查信息。

同步恢复使用精确执行ID。只有任务ID且首次业务读取失败时，通过正式授权的任务交接分页定位当前有权读取的真实E，只检查这些明确身份对应的本地原件，不遍历本地存储。页面有界读取，较早操作由用户翻页；未读历史不宣称没有原件。真实403继续受权限约束，无H的旧记录仍须使用精确执行链接。

## 跨存储边界与剩余限制

新派发先在Manager SQL保存耐久H，后台使用固定原件，经Core原子门建立计划；外部事实按当前SQL版本和领取fence恢复，不再依赖旧sync版本重放。Core单向关闭为未启动取消提供真实负面证据；缺少收据本身仍不证明没有派发。

旧sync曾建立外部计划而Manager回执缺失、随后项目版本推进的记录，仍需正式授权对账。当前取消也有独立窗口：Core关闭成功后Manager回滚，后台恢复并推进项目版本，原取消请求旧版本不能取得原ACK。安全封门不等于原命令已确认；界面保留未知原件。不能伪造ACK、更换键冒充原操作已确认，或全局放松CAS。

人工execution.review同样要求已有真实运行，不再隐式派发；其通用写入的原件恢复仍须独立完善。A2A、运维入口、精确设计采纳、项目创建、代码纳入CI关系、Reflection和全部运行/生产验证仍需继续完成。
