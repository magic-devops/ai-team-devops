# 项目编辑与原操作恢复

阶段：`T-project-editor-usability`，承接源码提交 `14c1dff`。运行验证按用户要求后置；当前记录源码设计、实现和静态审查，不代表测试、构建或实际界面验收通过。

## 用户操作

项目详情顶部集中提供进入工作台、编辑配置、变更状态和刷新事实。配置表单在独立弹窗中编辑，后台事实刷新保留当前草稿；名称、描述、路径有对应长度限制。项目状态继续使用“预览影响→确认变更”，选择目标和填写理由本身不提交变更。

遇到并发配置变化，先读取最新配置，查看与当前草稿的差异，再明确采用新版本。采用时保留草稿，下一次保存使用该版本。状态变更的预览绑定原项目、目标、理由和事实依据；修改目标或理由后重新预览。

保存中有同步操作锁，同一时刻只打开一个项目编辑器。关闭、重复保存、旧字段回调、进入工作区和组合页项目跳转都检查当前操作状态。详情关闭动画保留展示内容，同时立即撤销旧内容发起编辑和读取的资格。

## 未确认结果

配置修改与状态变更共用已有持久命令控制器，保存原目标项目、正文、版本和幂等身份。浏览器恢复记录按用户、租户、登录代次、目标项目与操作隔离，不保存 token。组合页允许在当前工作区 Q 中管理 P，实际请求仍明确指定 P，成功后保留工作区选择。

网络异常、服务端故障或不匹配的回执进入结果待确认，保留原件并锁住新的提交。只有“继续确认原操作”会重放同一请求；重新读取事实是独立的只读操作。原件重试后来收到权限或版本拒绝，也不能证明原提交未完成，因此继续保留原件。首次明确拒绝可以保留草稿并重新读取、确认。

刷新后重新打开项目详情，可以继续确认尚未结束的原操作。最新项目事实读取失败或权限被撤销时，恢复宿主仍在，旧缓存事实收起；不会因为隐藏业务正文而丢掉恢复入口。两个未决操作各自保留，恢复时一次处理一个。

回执使用现有正式合同校验。配置修改的结果为 `null`，状态变更核对原目标、理由和实际归档来源；二者均核对项目资源和版本。`query_generation=null` 可以表示写入已确认、查询索引尚待恢复，不把它伪装成读取成功。

服务端确认后，先清理本地恢复槽，再关闭编辑器。若浏览器存储清理失败，界面保持“保存已确认”，提供“完成保存确认”整理本地记录，避免重复发送业务变更。共享控制器恢复已验证成功记录时，即使清理失败也保留已确认回执。

本轮还修正正式任务计划的同类边界：未知原操作重试后的 4xx 保留原件；首次明确 4xx 与未知后的拒绝分别处理。

## 验证与边界

证据位于 `.sop-runtime/delivery-evidence/project-editor-usability/`，包括修改前快照、真实回执合同核查、控制器及消费者回归定义和独立静态审查。本轮没有运行 Node、测试、类型检查、构建或浏览器。回归定义和源码摘要不构成运行 GREEN，后续需从最新提交重新固定源文件并执行实际验证。

持久恢复限定当前浏览器标签和同一登录代次；不同登录代次不会自动读取或重放前一次登录的原件。损坏、不可读或无法保存恢复记录时停止新提交；仍需人工核查无法验证的原操作。实际存储配额、浏览器退出事件、焦点管理、窄屏排版和权限变更时序待实机验证。

项目创建仍使用旧接口，尚需独立补齐耐久幂等与回执恢复；本阶段只为其打开入口接入现有未决编辑的导航保护。精确设计文档采纳关系、并行 Agent/运维入口的真实运行关联、Reflection 接入及完整发布验收仍在整体待办中。
