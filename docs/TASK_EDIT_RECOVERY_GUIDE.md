# 编辑任务和找回原操作

在项目任务或独立任务列表中打开任务编辑，可以维护标题、说明、逐条验收标准、关联需求标准、依赖、计划日期及阻塞说明。负责人和记录状态保留快捷操作，使用同一任务的原请求恢复。

保存前读取明确的任务和规划依据。发生并发修改时，先查看最新内容，再明确采用当前依据；已经输入的文字和证据条件不会因为读取失败被清空。需求标准变化时需重新确认关联，不能按旧位置猜选。

如果保存后显示结果尚未确认，使用“恢复原请求”。它继续相同正文、版本和请求键，不会根据当前 Task 或讨论重新生成操作。当前任务、需求或项目摘要暂时读取失败时，恢复入口仍应显示；刷新当前数据不等于确认上一次保存。

出现已确认回执后，只需完成本地确认。即使随后刷新失败，也不要再保存一遍；本地清理失败时继续完成清理。权限变化会由服务端重新核实；恢复被拒绝时，原操作仍保留，拒绝响应不能被当作原保存从未发生。

从讨论采用到任务时，进入明确 Task 的编辑位置，保留原来源引用和讨论返回位置。未知操作使用已保存的原来源，不能换成当前新选的消息。

恢复数据保存在当前标签页的授权会话中，可以用于同一会话内刷新和重新打开页面。关闭标签页会话、清除浏览器数据或重新登录后，不保证自动找回；此阶段不声称跨浏览器会话恢复。账号、项目或任务切换时不会将其他作用域的原件用于当前操作。

本阶段沿用当前优先级、创建、删除、批量、排序及预约入口；它们未被描述为全部纳入任务编辑的恢复模型。当前源码还需要实际测试、类型、构建及浏览器验证，不能以源码审查代替稳定性验收。
