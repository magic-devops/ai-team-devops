# 需求拆解的本机草稿与原请求恢复

任务 `T-task-plan-recovery`，基线 `722dcb1e08601769407d0efd29669fa6029ee02d`。沿用现有任务拆解、成员身份与正式 `tasks.plan` 命令，补刷新、关闭重开和应用重启的恢复链路。

## 操作与状态

- 输入、选中项、负责人、前置任务、日期、验收映射与生成设置同步保存到本机。固定需求的最小快照、版本、修订与依据一起保存；生成建议保留来源及用量，未取得结果的预览请求保留原键。
- 拆解地址携带 `plan_requirement` 并保留当前项目、搜索和页面位置；刷新同地址可重开。工作台各读取状态均挂载“本机拆解与恢复”，即使当前项目或需求读取失败仍可查看保存内容、重试原请求。
- 普通草稿复用主页面持续更新的项目权限与读取状态，再读取同项目、同版本和同查询代次的需求后才可编辑。固定显示快照不代替最新查询的权限；权限撤回、主读取失败或代次变化立即阻断原编辑回调，原请求恢复继续独立保留。基准变化时显示固定原件，明确核对并采用最新需求；验收映射按文本重建，不能自动把旧草稿变成新范围。
- 创建前同步写入原内容、版本、请求键和讨论引用。未可靠保存时不发送。发送中断或响应不符合约定时保留未知状态，只能重试同一请求；后续 403/409/422 也不能抹除未知结果。
- 首次明确拒绝后，可显式返回编辑并核对最新基准。返回编辑及读取失败重试均等待项目和需求实际读取成功、与当前快照精确关联后才开放编辑，不用后台刷新期间的旧成功缓存兜底。未知结果不能清除或换请求。发送中不能关闭；未知原件已保存后可以关闭，稍后继续恢复。
- 已确认的任务回执持续保留，重开不会再创建。点击查看时重新读取当前项目和逐项任务，核实任务仍属于原需求后再导航；读取失败或父页面刷新失败均保留回执。
- 清除本地记录需要明确确认，仅限草稿、明确拒绝或已确认成功，不删除服务器任务。保存失败时有明确提示和“关闭未保存页面”确认，原有耐久记录继续保留。
- 保存失败的最新输入继续留在恢复宿主的内存中；后台版本切换、重建读取或读取失败不卸载宿主，也不把失败输入退回旧磁盘草稿。表单重新挂载仍可看到未保存项，可明确重试本机保存；成功前不能创建任务。强制刷新或明确关闭未保存页面仍会丢失未能保存的部分，离开保护与警告继续有效。
- 紧凑恢复卡片、可展开内容、状态文案、窄屏换行与中英日提示共用既有样式和组件。

## 记录边界与并发

本机 `localStorage` 身份由租户、用户、业务、项目和需求组成。重新登录的同一账号可恢复；当前令牌、登录修订和权限不写入记录，也不把本地记录当作权限或业务完成证明。读取与写入仍要求当前会话、路由和项目匹配；正式请求重新经过服务器授权。

每份记录最多 2 MiB；目录最多显示 50 条，已知直链仍可打开对应记录。编辑窗口持有浏览器 Web Lock，写前核对原始字节，避免多窗口覆盖；锁占用可重试。损坏、外部变更、超限、缺失锁或不可用存储均停止新写入，保留原件。浏览器存储被用户清除或设备丢失无法本机恢复；本阶段不提供跨设备同步，不自动迁移旧内存草稿。

上一份生成备份及尚未应用的批量负责人选择只在当前编辑器内保留；实际已应用草稿持续保存。保留原讨论引用不等于复制全部消息或权限，提交时由服务器核验精确引用。
