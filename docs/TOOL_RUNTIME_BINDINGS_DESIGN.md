# 开发工具固定运行配置

本阶段为源码实现与审查阶段。按用户要求暂不运行应用、测试、类型检查、构建、浏览器及外部工具连接验证。

## 使用流程

沿用紧凑协作工作台及统一派发设计。团队工具详情显示“运行配置关联”，由有权限的配置人员明确选择已有运行工作区和配置版本。任务派发列表显示同一工具的“平台执行”和“外部协作”两种实际可用方式；选定一种后继续核对执行位置、测试和计划。搜索、固定版本事实和不可用原因复用现有交互，避免另建一套工具派发页面。

工具名称和 tool 文本只用于团队登记与检索。平台执行使用关联的真实 AgentProfile.provider，绝不依据工具名称推断适配器、凭证、程序存在或可执行状态。例如名为 Zed 的工具明确关联 Codex 配置后，该次平台计划实际通过 Codex 提供方执行，界面显示真实提供方。

## 业务与权限边界

- 正式登记且 active 的 agent、tool 可关联。人员、user: 身份、未知类型、失效资源不可关联。成员类型创建后不可修改。
- 复用 member.runtime.bind / member.runtime.unbind、team-runtime-bindings、现有 AgentProfile 及关联代次，不新增重叠的工具配置数据库或执行器。
- 关联固定 workspace_id、agent_id、agent_version、profile_digest，预览及派发固定成员身份、关联依据与配置快照。执行位置仍须明确选择。
- 服务端持续校验项目配置权限、租户、运行读取权限、工作区 ACL、配置状态和版本。关联不授予 execute，也不改变目标策略、程序检测、审批、测试或验收。
- 负责人仍为人员或智能体；开发工具可作为执行资源，不能成为任务责任人。
- 工具停用会持久化解除关联并增加代次。恢复启用须明确重新关联；即使重新关联原配置，旧派发意图仍失效，不能通过 A/B/A 恢复旧权限。
- 已交接的执行继续使用原成员与配置快照。解除关联不停止实际运行；停止、取消和未知结果恢复仍按原执行控制流程处理。
- 修正已交接运行控制仍检查实时成员关联的问题：启动、重试、审批及实际 claim 授权校验运行固定配置和目标，继续检查项目、任务及执行权限；不再把已解除的团队关联当作运行撤销。未交接计划仍在预览、排队、交接处校验原关联。

## 界面状态

团队详情对智能体和工具使用同一运行关联面板，人员不进入配置流程。未关联工具在平台派发列表保留并显示关联原因。配置变化、不可读、停用、目标离线、提供方不可用、策略限制或任务执行条件不满足时，保留禁用原因，不自动改派。

“关联有效”仅表示读取时固定配置仍成立；不表示供应商认证或连接验证成功。平台方式统一显示“平台执行”，避免将工具类型混称为智能体。工具详情补充登记名称与实际提供方的关系说明。

## 合同与检查定义

写入使用既有 HTTP、SDK、CLI 合同。运行目录的读合同增加 nullable 的 member_name/member_kind，由项目登记身份生成，失效来源返回空值；派发列表和计划编辑器优先使用目录身份，不把任务负责人/排期引用的局部列表当作整个团队。SDK/CLI 检查定义确认明确配置版本、项目范围、原版本及原幂等身份传递，不自动选配置或变更依据。管理端服务检查按 agent/tool 两类覆盖配置权限、租户、运行 ACL、版本、摘要和代次。实际 HTTP 关联取代交接测试中的直接种子数据，覆盖预览、排队、交接、回执恢复、停用恢复、重绑幂等、测试证据和人工验收；这些是待执行定义，尚无当前运行结果。

前端检查定义覆盖工具详情入口、关联面板、人员排除、未关联工具原因、同一成员的不同派发方式，以及目标/策略/版本失效。浏览器渲染、键盘和窄屏验收等待验证窗口恢复。

## 剩余工作

现有运行关联编辑器仅保留当前打开的草稿，尚未纳入 W/S 的持久操作恢复机制；丢失保存回执后的跨窗口恢复仍需独立补齐。此次不把该流程声明为已完成稳定性验收。WorkBuddy、Zed、Harness、dsh、OpenClaw 等外部工具的自动适配及认证握手继续分别登记实现与验证状态。完整研发全链路尚未完成。
