# 需求拆解与任务计划设计（2026-10-16）

沿用已确认的紧凑协作工作台。需求详情内打开专用计划弹窗，手动、模板建议、AI 建议共享同一可编辑草稿，确认后只创建用户当前选中的内容，不重新生成。

## 四个关键状态

1. **准备计划**：顶部显示固定需求修订和验收标准，以及已有任务。手动增加条目；模板与 AI 是明确区分的建议来源。AI 显示实际模型、用量与错误，不在失败时伪装为模板成功。
2. **调整与预览**：每项可选择、编辑标题、描述、负责人、优先级、估算、起止日期、验收条件关联和前置任务。汇总选中数量、验收覆盖与依赖问题；删除/取消选择前置项后必须处理依赖才能提交。窄屏使用纵向任务卡片。
3. **确认与恢复**：保留打开时的项目版本、需求修订和请求幂等身份；网络重试不重复创建。409 保留草稿，展示最新需求和任务；明确采用最新基准后才再次提交，验收条件按原文本重新关联，不能把旧索引静默指向新条件。
4. **创建后跟进**：真实任务显示验收关联、日期和前置任务。依赖尚未交付时标识阻塞并阻止启动/完成；继续使用已有执行、日志、测试和验收卡片。计划来源、模型用量及编辑后的任务映射可追踪。

## 接口和归属

- `POST /api/v1/delivery/task-plan-preview`：登录、项目 write 权限；输入 `requirement_id, expected_version, idempotency_key, generator(template|ai), mode, max_items`。输出 `id, version, requirement_revision, requirement_basis, requirement_snapshot, items, source, model, provider, usage, warnings`。预览不创建业务任务或执行进程。
- 预览请求在 SQL 中记录固定快照与生成结果。幂等范围是用户/租户/项目；重复成功请求复用结果，生成中或失败请求不静默重复模型调用。模型失败明确返回错误；新的主动生成使用新 key。网络调用不持有业务工作区写锁。
- `tasks.plan` 复用现有事务/CAS/receipt，增加可选 `requirement_revision, requirement_basis, preview_id`；旧手动调用保持兼容。预览来源由服务端记录验证，不能由客户端伪造。确认时验证需求基准、合法成员、日期、验收索引、依赖存在及无环，然后原子创建全部选中项。
- `TaskDraft` 增加可选 `key, acceptance_criteria(int[]), depends_on(str[]), starts_on, ends_on, blocked_reason`。依赖可指本计划 key 或当前项目既有任务 ID；确认后转换为实际 Task ID。新增规划字段存入 DeliveryWorkspace 的 `task_details`，Task 继续是唯一业务任务记录。
- 创建后可维护关联、日期和阻塞原因。关联修改必须带当前需求 basis/revision，校验环路及前后依赖日程；可移除已删除的前置任务，恢复被阻塞工作。关联变化永久作废旧执行证据，需要重新派发与验收；旧任务的空或部分规划元数据不妨碍查看和补齐。
- AI 只调用已有 `llm_gateway.llm_chat(task_type=plan, cache_ttl=0)`，所有输出先经同一结构校验；不调用旧 generate-tasks 写入路径，不运行模型生成命令。当前实际网关按环境路由；配置页/v2 路由全面收敛仍是独立待办。

## 验证约定

后端覆盖固定内容创建、重复请求、跨租户/项目/只读拒绝、需求变更、AI 结构/额度/提供商失败、失败不降级、依赖缺失/环路/日期、前置任务完成门禁。前端覆盖草稿变更、选择、验收重映射、稳定重试身份和缺失依赖；实际浏览器验证模板调整后创建、冲突恢复及 390px 界面。AI 自动测试使用 stub provider，不宣称生产账户真实推理已验证。

Ruling: 本增量执行用户既定“拆解先预览调整、统一模型网关、幂等及版本检查”的计划，沿用当前组件库与本地设计验证。此前第三方设计上传已被拒绝，不再次上传项目设计。保留全目标及未完成项，不因本增量通过而宣称产品完成。
