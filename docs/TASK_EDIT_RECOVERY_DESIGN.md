# 统一任务编辑与原请求恢复

阶段 `T-task-edit-recovery`，基线 `fd5247ad7a8e21c1ad0245885eb21bec487b155a`。延续已确认的紧凑协作工作台、主题及三语体系。用户要求先完善源码和操作流程，测试、应用、类型、构建及浏览器验证继续后置。

## 实际断点和归属

普通任务定义使用通用 `DeliveryEditor`，原值、版本及请求键只在挂载表单中保留。刷新即失去恢复原件；当前 Task 读取失败又会卸载维护计划。更外层项目/需求读取失败、索引未就绪和讨论采用状态丢失，也会绕过任务编辑入口。负责人和状态快捷更新虽走正式命令，同样缺少固定原件及严格回执。

本阶段仍使用唯一 `task.update` 业务命令、真实 Task、原需求/规划依据和现有事件/回执。不增加另一套任务状态或专用编辑数据库。编辑与恢复使用同一个任务原请求控制器；新写入需要当前精确数据及写权限，恢复既有请求不以当前 GET 成功为前提。

## 正式合同

完整定义原件明确包含 `id/title/task_basis/planning_basis/description/acceptance_criteria/requirement_criteria_indices/depends_on/starts_on/ends_on/blocked_reason`。负责人和状态快捷更新分别使用明确的 `id/task_basis/owner_id`、`id/task_basis/status`，继续直接操作，无需为快捷修改新增确认弹窗。

标题纳入正式 `TaskEdit`：提供时为去首尾空白后的有效 UTF-8 文本，长度 1–256 Unicode 码点，拒绝显式 null，并要求当前 Task basis。标题变化参与既有接受阶段、执行和交付证据失效门禁；不能用通用更新绕过验收。优先级与已有 basis 的耦合语义不在此切片重定义；列表优先级 PATCH、创建、删除、批量、排序和独立预约命令不宣称已纳入本原件模型。

原请求固定 `action/payload/intent.version/intent.key`；讨论采用时还固定原 `source_reference` 五个字段，不能从新的讨论选择重建它。严格回执为原 `task.update`、同项目/Task、`result:null`、唯一 Task affected ref、`applied_version=原版本+1`，当前版本不得早于它。当前读取、任务移动、删除或已完成状态都不能代替原回执。

Task 定义的合法正文可大于外部报告的 48 KiB，独立原件预算为 1 MiB，保留数据上限为 3 MiB。它只存本次原正文和回执，不复制整个工作区或需求快照。无法安全保留原件时不发送。

## 连续操作与恢复

1. **打开和编辑**：列表/关联入口可直接定位任务编辑。标题、说明、逐条验收标准、需求关联标准、依赖、日期与阻塞说明集中处理，保留当前项目和返回位置。新读失败保留错误及恢复入口，不把不可读需求当成独立任务。
2. **固定写入**：使用明确 Task 和规划依据，在发送前保存完整原请求。发生确定拒绝时保留原字段；读取最新后，用户明确采用新依据，再生成新键。负责人及状态的拒绝重试保留原选择，只提交对应快捷字段。未知结果不能采用新依据或替换请求。
3. **刷新和失读**：同一授权会话内重挂/刷新可以从 scoped 保留数据发现 Task，独立显示恢复内容，不需要 Task、需求、讨论或项目摘要 GET 成功。恢复继续原正文、版本、键和来源；服务端重新检查当前权限。403 或 404 的重放响应不能证明原请求从未写入。
4. **确认和清理**：已验证的 `succeeded` 回执保留到任务 owner 明确完成本地清理。清理失败继续显示已确认状态，只重试清理；刷新失败不能将已确认操作改成 unknown，更不能再发新命令。编辑草稿与未知写入互斥仍分别通知，关闭草稿不能释放未知操作。

同项目/账号会话/Task/位置的编辑与恢复 consumer 共享控制器，存储还在每次写前核对原值，防止旧 idle 实例覆盖已有原件。最后 owner 卸载时使旧回调失效；重新挂载由保留数据恢复。捕获的旧项目、账号及已卸载回调不能获得当前操作资格。

启动门禁优先处理结果未明及已确认待清理的原件。失读兜底还可显示确定拒绝的原字段，保留父查询的重试；确定拒绝不会被归为未知写入。普通偏好设置的存储事件不会使编辑控制器和精确读取失效；账号或位置确实变化才使旧操作失效。

保留层沿用现有 `sessionStorage`，键绑定租户、账号、授权会话代次、项目和 Task。这里承诺同一授权会话内的刷新和重新挂载，不承诺标签页会话结束、重新登录或浏览器完全重启后的自动恢复。原浏览器数据不会因此被清理或当作已成功；跨授权会话的显式恢复属于独立后续设计。
