# 反思收集与固定输入使用说明

阶段 `T-reflection-intake` 已纳入 2026-10-28 的剩余源码整理与分组提交。本文描述正式源码合同；运行、类型、构建和浏览器验证仍按用户要求等待窗口，不能将源码审查称作功能通过。当前清单与提交回执见 `REMAINING_SOURCE_REVIEW.md` 和项目记忆。

反思用于记录人或智能体的观察与改进建议。“已收集”只表示规范收件处理完成；“固定输入”只表示明确选中的原件引用已保存。它们都不代表测试、质量验收、部署通过或规则已经应用。

## 收集

通过 SDK 的 typed reflection helper 或 CLI `reflection` 入口构建 `sop.reflection.recorded`。提交者必须保留同一原 event ID、原发生时间和原 JSON 字节。客户端先写入已有 SQLite EventOutbox，再投递；断网或回复丢失时沿原 outbox 恢复，不换 ID 重新生成。

字段为类别、标题、观察、改进建议和可选的任务/执行引用。项目和提交身份由真实认证决定。引用必须是同项目真实对象；执行还需当前 runtime 权限。陈述中写“测试通过”不会生成实际测试证据。

收到 durable receipt 只表示原件已存储。处理仍 pending/failed 时，从 Intelligence 的事件收件查看原因和实际尝试。规范反思处理成功才进入已收集目录。旧的任意 payload/无 handler 原件不会自动迁移成新反思；应重新审阅后以新 ID 提交规范事件。

## 查看与核对

在当前真实项目打开 Intelligence → 反思。已收集目录支持类别、发生时间与固定窗口分页；目录总数包括原文受限的脱敏记录，不能当成当前可用正文数。

点击指定反思独立读取原件，不受当前目录页限制。详情将提交者陈述、服务器收集事实及当前来源可用性分开。事件原件通过唯一事件回执查看，返回保留当前项目与筛选。

来源权限不足、对象消失、原件损坏和服务暂不可用分别显示；没有权限时隐藏旧正文和来源目标。执行后来换绑不会给旧反思扩权。反思与固定选择的历史身份不会因 Task 删除而被替换成别的对象。

## 固定后续分析输入

明确核对一份 exact 反思后加入当前选择，可以跨页添加；目录上的受限壳不能直接采用。填写选择标题和依据，预览所有成员，再执行一次“固定输入”。最多32份原件，单份64KiB、合计2MiB；任一成员失效会拒绝整个新选择，不保存部分成功。

服务端保存有序原 receipt/digest/成功 attempt 引用，不复制正文。固定输入详情保留原成员和数量；后来失源时标为不可用，不自动补位。更换选择需新建输入。页面明确显示尚未运行蒸馏或应用规则。

## 结果未知时

保存前浏览器先持久保存原请求。若操作已成功但回复丢失，页面会显示“原请求结果尚未确认”，提供“恢复同一请求”。恢复保持原正文、原版本和同一键；当前目录、原件或来源服务不可用也不要求替换请求。

确认匹配的原 ACK 后才解除恢复状态。刷新当前 GET 不等于确认原操作；不要通过换键绕过未知结果。新写明确冲突时保留草稿，重新读取并由用户明确采用新的依据后才准备另一请求。

SDK/CLI 固定输入只接受完整正式 ACK：同项目、动作、应用版本和唯一 input 身份，选择数量与原请求一致；空200、截断或不匹配回执都不计作确认。原命令中的合法原键、Python整数版本及显式 `source_reference:null` 保留原样，不因客户端新校验无法恢复。

## 本阶段边界

旧全局蒸馏、JSONL提案和自动规则应用入口同期退役，不保留兼容路由。历史用户文件保持原样。Web 本阶段提供收集接入说明与回执导航，真正投递通过 SDK/CLI outbox；没有假手工收集按钮。

模型蒸馏、规则提案/审核/应用、生产平台身份及基础设施接入后续逐项完成。实际浏览器视觉、390px焦点与主题对比、其他数据库及长期规模未因 SSR/构建通过而被视为已验证。
