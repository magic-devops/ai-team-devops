# 项目交付工作台

入口：管理台「研发全流程」`#/dev-flow`。

本轮把原有的聚合导航页升级为可操作的交付工作台。Manager 的 Project、Requirement、Task、Issue 继续作为业务记录；新增流程元数据关联这些记录，不建立第二套需求/任务库。

## 已实现

| 范围 | 可用操作与约束 |
| --- | --- |
| 项目 | 真实 Project 名称、简介及交付目标、负责人、起止日期；按字段保存，项目选择沿用现有控制台 |
| 项目资料 | 仓库、文档、设计及其他链接；编辑、分类筛选、可恢复归档；配置权限、版本冲突与来源记录 |
| 交付待办 | 本人/团队的工作、可评审阶段、当前有效待验收执行及阻塞事项；分类去重、实际日期、准确跳转 |
| 团队 | 读取实际项目人员及租户管理员；登记智能体与工具；分配责任人与查看未完成任务负载 |
| 需求 | 创建、编辑、验收标准、优先级、负责人、截止日期、里程碑、阻塞原因、问题来源 |
| 需求辅助 | 明确选择 AI 或规则；采集、评审和原型先预览、编辑、选择后确认；保存生成来源、实际用量与历史，旧建议基准变化后不能直接采用 |
| 设计 | 产品设计、UED 原型、架构设计、代码变更、测试报告、运维手册的内容与链接登记；按修订保留历史 |
| 拆解 | 手动/模板/AI 建议共用可编辑计划；逐项选择标题、范围、负责人、优先级、估算、日期、验收关联和依赖；确认当前选中内容后原子创建真实 Task |
| 执行 | 任务内保存派发计划，选择既有智能体或命令/测试节点、远程设备；同步与启动分离，真实运行证据自动回写 |
| 测试与验收 | 测试结果与人工验收分离；任务未完成、高优关联问题未解决、最新测试失败时不放行 |
| 发布 | 登记版本、环境、产物链接、验证结果、回退方案；缺失时不能通过发布阶段 |
| 运维 | 运维手册与交接评审；保留实际问题记录 |
| 问题回流 | 问题转需求保留 source_issue_id，同一问题去重；不自动关闭原问题 |
| 视图 | 概览、交付待办、需求列表、阶段看板、里程碑、项目资料、混合团队、问题反馈、右侧详情；搜索与筛选 |
| 交互 | URL 定位视图、需求、任务、问题与详情标签；刷新和返回恢复定位；保存失败保留输入；冲突展示最新数据并允许明确核对后采用新版本 |
| 语言与主题 | 中文、英文、日文；沿用主题变量；窄屏布局、键盘焦点与减少动画设置 |
| 权限与模型 | 旧业务读写及配置权限统一；模型配置按租户/项目隔离并用于实际调用；缓存不重复计费；主壳与独立子应用会话切换隔离 |
| 工作流人审 | 代码审查、迭代和问题分诊的实际类型信号；保留意见、审核人和去重标识；超时继续等待，恢复等待状态，不替代业务任务验收 |

生命周期固定为：需求评审 → 产品设计 → UED 设计 → 架构设计 → 任务拆解 → 功能开发 → 测试验证 → 质量验收 → 版本发布 → 运维交接。

阶段推进需要对应条件满足，并由有审核权限的成员提交评审意见。将任务标记完成不会自动视为需求验收或发布成功。历史上已标记完成但没有流程证据的需求，明确显示为历史记录，等待正式评审。

## 一致性与访问控制

- `GET /api/v1/delivery/workspace`：读取当前项目交付状态。
- `GET /api/v1/delivery/inbox?scope=mine|team`：纯读取当前项目个人或团队交付事项。
- `GET /api/v1/delivery/execution-targets`：读取当前身份可访问的执行工作区、智能体版本和设备。
- `POST /api/v1/delivery/task-plan-preview`：生成可调整的模板或 AI 任务建议，保存固定需求快照与生成凭据，不创建业务任务。
- `POST /api/v1/delivery/commands`：提交 action、payload、expected_version、idempotency_key。
- 上述入口均使用现有登录身份、项目成员校验和 `X-Project-Id`，所有业务记录按 tenant_id/project_id 查询。
- 查看权限沿用项目访问权限；开发者可编辑；项目管理员、产品经理和 DevOps 可评审；团队配置限项目管理员及租户/超级管理员。
- 项目版本通过条件更新避免丢失修改，操作结果与事件、幂等凭据在同一数据库事务中保存。
- 表单固定打开时的版本；同一次未确认提交重试时保留原版本与幂等 key。冲突不会静默覆盖最新数据。
- 需求标题、描述、验收标准变化后开启新修订。测试/验收阶段的任务范围或状态变化会使原验证失效。
- 旧页面或 API 修改规范业务记录后，读取工作台时会比对内容指纹，显示有效的重新评审状态；下一条工作台命令将该失效状态持久化并纳入事件。读取本身不写数据库。
- 最新失败的设计/测试产物不满足门禁。链接仅允许不含账户口令的 HTTP(S) 地址；前端再次过滤可执行链接。
- 执行器测试报告绑定 task、execution、run 与证据摘要。任务内容变化、任务转属其他需求或重新派发后，旧报告保留为历史并标记失效，不能继续满足测试门禁。

## 任务派发、执行回写与验收

1. 打开需求详情的「任务与分配」，在任务下准备执行计划。选择已有执行工作区、固定版本的智能体，或配置命令节点及显式测试节点；可选远程设备。计划保存时固定需求修订、验收条件和任务内容。
2. 保存计划仅写入 Manager。同步操作通过已有运行模块创建执行信封与运行；重复同步复用原派发人和计划 ID，不重复创建运行。必须单独启动才执行进程。
3. Manager 每 5 秒检查已关联、未关闭运行的真实版本，只有发生变化才写入业务事件；页面定期刷新。后台不会自动派发尚未同步的计划，也不会启动进程。断线后可手动同步恢复。
4. 运行成功进入「待审查」，业务任务仍是进行中。审核人核对节点退出码、日志和固定快照，填写意见后通过验收，才计入任务完成。仅显式测试节点生成测试证据；普通 Agent 文本不当作测试报告。
5. 失败运行自动创建一个关联问题；重复同步不重复创建。问题转需求保留来源且去重，原问题继续保持未解决，需单独处理。
6. 原派发人失活后，具备当前项目及执行工作区权限的管理员可以同步、审查既有运行，或取消待派发计划。尚未建立运行的旧计划不能借其他身份继续派发，需取消并重新准备。

执行权限沿用已有运行模块：默认仅 `super_admin` 获得执行权限，其他身份需要已有工作区成员/授权配置；没有为了工作台扩大权限。人工验收还需项目 approve 与运行模块 approve。生产角色授权治理仍需完善。

SDK 提供 `delivery_workspace()`、`delivery_execution_targets()`、`delivery_command(body)`；CLI 提供 `sop delivery workspace`、`sop delivery targets`、`sop delivery command --file <json>`，均沿用相同作用域、版本与幂等命令。API 契约位于 `apis/openapi/openapi.yaml`。

新增表：`delivery_workspaces`、`delivery_events`、`delivery_receipts`、`delivery_plan_previews`、`requirement_assistance`。通过现有 SQLAlchemy `create_all` 创建，未改变既有业务表列。生产库上线仍应按团队迁移与备份流程执行，并验证 MySQL/OceanBase；本轮数据库测试为 SQLite。

## 需求拆解与任务计划

- 「拆解任务」打开专用编辑器。切换手动、模板、AI 方式保留当前草稿；生成新建议后仍可逐项编辑，上一份草稿可恢复。展示固定需求修订、验收覆盖、缺少的验收条件与既有任务数量。
- 确认只提交选中的当前内容，不重新推导模板。日期有序、依赖存在且无环、前后任务日期相容；取消选择或删除前置项后必须修正关系。服务端来源凭据、需求 basis/revision、项目版本和幂等 key 同时参与校验。
- 每个需求返回内容 basis，包括尚无交付 flow 的旧需求。需求标题、范围或验收条件重排后，旧基准不能静默创建错误关联。冲突保留输入；明确采用最新基准时按验收条件文本及重复出现顺序重新匹配，删除的条件不会转绑其他条件。
- 计划生成凭据在调用模型前单独提交，不持有业务工作区写锁。相同请求成功时重放结果，生成中或已失败时不重复调用模型；用户主动「重新生成」才使用新请求身份。生成后再次核验账户、项目权限和需求基准。
- AI 使用现有 `llm_gateway.llm_chat(task_type=plan, cache_ttl=0)`，记录实际 model/provider/usage。模型输出经严格结构与依赖校验，缺省任务 key 规范化后再返回。模型失败、额度不足及非法输出明确返回，不静默降级为模板成功。模型管理页的当前项目配置已用于实际调用；v2 治理策略及生产执行路由仍需继续统一。
- 创建后「维护任务计划」可修改验收关联、依赖、日期及阻塞原因。修改关联需要当前需求基准；已删除的前置项可解除或替换。同次清除依赖和改期按最终图原子校验。关联变化永久作废旧执行证据；同值关联与单纯日期保存不会作废已验收结果。
- 旧任务允许空或部分规划元数据。没有来源凭据时不伪造来源；查看、编辑和执行入口继续可用。详情展示原验收快照、计划来源与可点击的前置任务，未交付依赖阻止开始和完成，通用任务写入也受约束。
- SDK `delivery_task_plan_preview(body)` 与 CLI `sop delivery preview --file <json>` 复用同一契约；CLI 要求显式 generator，重试复用原 JSON。设计及四种交互状态见 `docs/DELIVERY_TASK_PLAN_DESIGN.md`。

## 进度显示口径

- 任务进度：关联任务 completed 数 / 关联任务总数。
- 已验收：当前有效修订已进入发布或运维阶段。
- 已发布：当前有效修订已进入运维阶段；历史发布记录继续保留。
- 工作台历史：最近 200 条交付事件中的观测值，界面取每天最后一次观测，最多显示 12 天。不会补造没有记录的日期。
- 旧 Sprint 与 dev-flow 燃尽接口已移除由当前状态反推的起点/终点，只返回当前实际观测点；缺少有效起止日期时不绘制时间曲线。理想线以当前任务范围为参考，不冒充初始基线。
- 人员容量暂为规划值；智能体容量可配置。工具登记不代表完成连接、鉴权或可执行能力探测。

- 任务计划实际浏览器验证：模板四项调整后只创建选中两项，标题/范围原样保存，后续任务显示前置阻塞；制造需求重排冲突后保留草稿、查看最新内容、明确采用并将原验收条件从索引 0 映射到 1，最终只创建一项。创建后日期维护实际保存成功；桌面和 390px 编辑器、键盘关闭可用，修正了新弹窗背景透字。

## 仍未完成的全链路能力

以下内容没有在本轮冒充已实现：

1. 各厂商实际账户登录与生产连接验证、统一 Agent 身份绑定、生产角色授权治理，以及更完整的流式干预与恢复交互。现有适配器已接入业务派发/回写；原生和远程进程已实测，不能据此宣称所有厂商实机接入完成。
2. AI 任务计划、需求解析/评审/原型及项目模型配置已接入实际网关，Embedding 和数据问答复用项目配置与审计；生产账户推理、v2 治理策略与实际执行路由的统一、更细的用量归因仍待完成。工作流可恢复已落盘的等待状态；模型生成进程中断后的自动恢复仍需增强，当前不自动重放模型调用，可明确主动新建生成请求。
3. CI 测试报告与构建制品的可信采集、签名及关联具体代码提交的验收。当前区分人工登记和执行器测试证据；执行摘要及退出码不是外部 CI 签名证明。
4. 真实部署执行、灰度发布、回滚编排及环境授权。登记发布记录不会触发基础设施操作。
5. 告警自动诊断、自动修复执行、智能问题分流和无需人工确认的需求入池。目前支持人工问题回流与去重。
6. 跨入口统一事件流、连续每日历史快照、计划基线冻结、依赖甘特图、成员日历与工时容量、万级需求的服务端分页。
7. 完整生产压测、MySQL/OceanBase 验证，以及所有主题、浏览器和屏幕尺寸的视觉回归。
8. 项目组合与项目归档治理、归档后的协作及保留策略，以及项目详情中需求/迭代/风险的进一步统一整合。项目资料的可恢复归档与个人/团队交付聚合已实现，不等于项目本身的完整归档治理。旧业务的作用域、会话竞态和需求辅助已修复；旧工作流的超时自动通过已移除，工作流结论仍不等于业务任务完成。Temporal worker 及其作用域审查合约尚未实现，接口明确返回不可用。
