# 从运维建议进入真实处置

当前为 T-ops-remediation-intake 源码阶段，未运行测试、类型、构建、浏览器或真实运维动作。

在当前项目的运维中心评估策略后，从“运维建议记录”选择建议，核对来源和问题标题，再“纳入问题”。同一条来源只建立一个真实项目 Issue，已经纳入时打开原问题。建议中的旧 verified、退出码或健康字段仅是旧记录/自报信息，不证明实际执行、测试、探针或回滚成功。

在正式问题详情选择运维来源证据，使用既有诊断功能；人工审核后采纳到需求池，再拆解、分配和派发正式任务，执行测试并验收。实际部署、灰度和回滚使用项目发布工作台；问题不会因为登记建议自动关闭。本阶段没有自动运行旧 action 字符串。

来源变化或项目版本冲突时保留输入，重新读取并明确采用后再确认。超时或回执未知时，保持原版本、正文和幂等键，使用“恢复原请求”。确认原问题后，使用“应用回执并打开问题”。独立恢复入口在来源/列表无法读取时仍保留，不能用新问题代替未知请求。恢复限同一授权浏览器标签页会话，账号或项目切换后旧回调不能继续提交。

暂时无法恢复时可以“保留操作，稍后恢复”返回列表；原请求不会清除或重发，后续通过“已保存的原请求”继续核对。

旧自愈动作的 approve/apply/verify/rollback 与策略 apply 接口已退出；策略评估和治理任务预览保留。`self-heal/tasks` 的实际创建模式返回正式纳入入口提示，不再绕过固定来源和幂等合同重复生成任务。

SDK：`delivery_ops_intake_source(source_id)` 读取当前固定来源；`delivery_ops_intake(body)` 提交保存的完整原请求，并校验回执项目、来源摘要、问题 ID 和原应用版本。CLI：

```text
sop delivery ops-intake-source --source-id <来源ID>
sop delivery ops-intake --file <已保存的原请求JSON>
```

JSON 恰含 action=`issue.ops.intake`、expected_version、idempotency_key、payload。payload 恰含 source_id、source_digest、title、description、severity（P0–P3）。先保存完整 JSON；CLI 不补版本、摘要或键，也不改写文件。认证和项目范围沿用已有客户端配置，不能把凭证写入原请求。

固定来源是脱敏、完整、有大小限制的追加式 SQL 记录。源文件删除或变化不影响已成功原请求的回执重放；原 Issue 被删除时不会自动重建。GET 不修复、不重放、不触发执行。

Runbook 的“处置记录归集”只统计来源记录。旧自愈 verified 等状态显示为“仅来源自报”，不能填平执行证据缺口；确认和归档记录不代表执行或验收通过。异常 JSON、非有限数字和无效 UTF-8 来源会明确拒绝，修正来源后再读取。

仍需验证真实 HTTP/数据库回归、SDK/CLI、类型、构建、浏览器焦点与窄屏。策略自动执行、旧 RCA 验证入口、完整自动运维及生产环境接入继续作为后续范围，不能将本阶段理解为全流程或生产验收完成。
