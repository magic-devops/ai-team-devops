## 已核实的问题与设计

TaskDispatchHost 当前先选择交付方式，再选择成员。禁用的方法只显示不可选，任务门禁、绑定失效、无可用执行位置等原因没有集中展示；外部方式的详细 reasons 也没有在选择处消费。绑定有效不等于当前存在可运行目标，用户可能直到计划编辑器才发现无法执行。

将方法与资源合为一次明确的单选：平台成员、外部协作成员、直接配置 Agent 和手工命令计划。每项展示当前真实配置、固定版本、可选执行位置数及不可用原因；直接配置与命令仍在现有编辑器完成明确选择。选择不自动派发，不宣称认证已完成。Agent 和工具的相同成员身份按执行方式分别展示。

输入名称、工具或工作区即可在已读取事实内筛选，不发新的查询、不改变已选项。默认展示前 40 项，显式查看更多；可用项优先，原目录顺序稳定。筛选隐藏已选项时仍显示当前选择，不自动选择第一项。采用标准单选输入、明确标签、可见焦点与窄屏单列；实际键盘、焦点及渲染待窗口恢复核验。

## 准入与恢复

可用性复用 executionTargetProblems：任务门禁、运行读取、活跃外部工单、运行政策、实际 provider 程序发现、绑定状态及 Agent 固定版本都必须满足。原因在选项旁展示，原始 code/message 按需展开；不把空列表或失败读取伪装成可用。外部方式独立消费它的 can_dispatch 和成员 reasons，不因平台能力读取失败而隐式转换方式。

继续时重新读取相同来源与实际能力；原 factsKey 变化需明确采用再选。复核返回后再次检查账号、路由、写权限、其他编辑 scope、原选择所有者及命令阶段；不可用选项不能通过旧回调继续。当前派发自己的编辑 scope 不阻断自身操作，其他 scope 会阻断；关闭未发送窗口不依赖当前写权限。

计划预览、正式确认、版本、幂等身份及未知原件恢复沿用现有实现。当前外部 W 仍不是自动执行适配器，不能通过新界面绕过停止声明、W/E 互斥或验收。
