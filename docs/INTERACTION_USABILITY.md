# 需求与任务工作台交互完善

阶段：`T-interaction-usability`。采用已确认的紧凑协作工作台方向，继续使用现有主题、Ant Design 组件和正式交付服务。

用户本轮明确要求先完善代码与设计，测试待内存和共享验证窗口恢复后执行，再做阶段提交。因此本记录区分“源码已实现”和“运行验收通过”：本阶段没有运行测试、类型检查、构建或浏览器验证。

## 操作路径

| 场景 | 现在的操作与反馈 |
|---|---|
| 需求工作台 | 四个阶段均可直接进入；只标记当前页面，不根据需求数量推断某个阶段已经完成。指标使用真实汇总，“登记完成”与交付验收分开。 |
| 需求拆解 | 选择需求后，明确点击进入正式研发工作台的该需求任务页，再使用“拆解任务”编辑计划。选择本身不调用 AI 或创建任务。卡片入口也进入同一条流程。 |
| 编辑任务计划 | 保留可编辑预览、验收标准映射和依赖检查；通过已有 `tasks.plan` 命令提交。需求页旧的直接生成面板及其调用已经移除，不再维护第二套生成交互。 |
| 返回需求 | 返回原需求阶段及关键词、状态、优先级和原项目；只接受本地受限路由。保留旧回调时，切换账号、登录代次或项目后不会导航。未决提交沿用正式工作台退出保护。 |
| 修改任务 | 看板拖动及列表状态、优先级修改显示保存中或真实拒绝原因。重复点击有同步锁；失败保留原记录，不显示虚假的移动成功。 |
| 任务返回 | 详情返回保留实际看板入口及四个筛选条件；筛选立即写入地址，不为每次输入新增历史记录。 |

正式任务计划的写入回执未知时，手工、模板和 AI 来源都保留原项目、请求正文、版本、幂等身份及可选讨论来源。编辑、取消、生成新预览及旧回调不能替换未决原件；只能明确重试同一原件。回执按现有命令合同及实际生成任务集合校验；不完整或不属于原命令的成功响应仍保留为未知。已确认成功会结束原未决状态，父级刷新出错不会把成功重判为未知。这里复用现有命令合同，没有新增第二套任务状态。

任务快捷修改目前仍使用原 PATCH 接口，该接口会触发 webhook，不能安全地自动重发。未知回执时只提供读取当前记录和进入详情，读取不会解除未知锁，也不宣称已证明原请求完成。这个保护只在当前组件内存中生效，跨强刷的持久恢复仍需后续正式命令改造。

## 页面状态与恢复

| 状态 | 界面行为 |
|---|---|
| 未选择项目 | 提供项目入口，业务读取按既有项目上下文门禁执行。 |
| 当前权限或项目失效 | 搜索与需求页收起业务正文和旧缓存，提供项目恢复及只读重试。不会把拒绝显示为空数据。 |
| 搜索的可选语义服务失败 | 保留输入、模式切换及关键词分支；失败分支不显示缓存结果，可独立重试读取。 |
| 普通需求列表失败 | 保留筛选输入和定向重试，隐藏旧需求卡片及评审、规划选择；批量操作不使用失效缓存。 |
| 汇总未取回或读取失败 | 数值显示“—”，不把局部筛选列表冒充项目总量；汇总失败可单独重试。 |
| 治理分析未取回或读取失败 | 隐藏健康分和风险表正文，保留读取状态与重试，不能显示假零分、健康或“无风险”。 |
| 已确认有效空结果 | 才显示对应空态或零值。 |

四阶段导航采用原生链接、可见焦点、当前页语义及窄屏两列布局；汇总使用语义化指标列表。新增局部文案覆盖中文、英文和日文。上述描述是源码设计和静态检查结论，尚未证明实际排版、键盘路径或移动端体验。
