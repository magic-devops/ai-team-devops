# 项目查询与详情

交付工作台的项目概要、需求目录、任务目录和精确详情分别读取。概要统计覆盖当前项目的全部工作，列表页只载入当前窗口。页面中已验证完成仍要求当前有效证据；任务状态“已记录完成”不会直接计入交付进度。

## 查找和返回

需求列表按关键词、阶段、负责人等条件在服务端筛选，再分页。看板每列独立读取，列数量来自完整匹配范围。URL保存筛选、排序、游标和选中对象；详情使用精确ID，位于后续页面的任务也可直接打开。成员、里程碑、资源和依赖候选使用有界目录；已选对象通过ID补取。

可变列表的游标固定在查询代次，项目变更后旧游标会明确失效。此时重新读取第一页，不能将新旧窗口拼成一个目录。历史活动仍使用其独立的固定上界游标，历史观察序号与项目版本、查询代次分别表达。

## 编辑和提交

草稿固定在打开时的内容和版本。并发变更后先核对差异，再明确采用新依据；结果未知时保留原请求与幂等键重试。成功回执包含原动作、原对象、动作结果和受影响对象；回执的 applied_version 固定在原提交，version/query_generation 为当前元数据。重放不从当前列表推断创建结果。旧回执缺少结果时明确返回 delivery_receipt_result_unavailable。

## 查询数据维护

原需求、任务和问题继续由业务表管理，查询索引是可重建的派生数据。相关写入在同一事务中更新它；即使优先级变动未产生新的进度点，目录也会刷新。查询失败会回滚本次业务写入，事务或保存点回滚不会留下超前代次。

索引缺失或版本不符时，项目概要仍可读取，但统计为未知。具有项目配置资格的成员可显式重建，只替换查询数据，不修改需求、任务、运行、验收、活动或进度历史。query_rebuild 是独立权限：归档项目可维护派生查询，业务编辑仍禁用。普通GET不自动修复。完整 workspace 保留为工具的明确导出，页面和保存后的恢复流程不依赖它。

当前分页提供首页和下一页，浏览器返回会恢复原URL窗口。质量与版本目录及选中证明采用独立有界读取，见 [质量与版本目录](DELIVERY_QUALITY_RELEASE_GUIDE.md)。人工审查历史、进度基线及需求影响历史仍有待进一步限定的计算成本，分别记录。窄屏结构和三语文案有源码及组件测试，390px真实渲染仍待实机验证。

HTTP、SDK和CLI均使用当前租户及明确项目上下文。执行详情另外核验当前运行工作区权限。接口清单见 [OpenAPI](../apis/openapi/openapi.yaml)，设计和验收边界见 [查询设计](DELIVERY_QUERY_DESIGN.md)。
