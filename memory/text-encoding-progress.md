## 原因与修改

- 截图中的 `ai-sop/specs/ai-collab/PROMPT_SPEC.md` 源文件中文正常；规范文档接口使用 Windows 默认 CP936 读取 UTF-8，并以 `errors="replace"` 吞掉解码错误，造成正文乱码。
- 规范文档、自定义文档、规则、脚本及旧版文档接口共用 `sop_manager/text_files.py`：优先 UTF-8（兼容 BOM），历史 CP936/GBK 文件通过 GB18030 兼容；无法解码时返回 422，不返回可被编辑器保存回源文件的替代字符。
- 脚本及管理端剩余隐式 JSON 写入明确使用 UTF-8。接入、质量、网关、指标、运维、标签、编排、会话、通知、认证配置与项目状态的隐式读取改用统一解码函数。Skill 存储复用同一函数；外部 Skill 导入仍严格要求 UTF-8。
- 系统源码扫描的异常回退读取明确指定 UTF-8，避免再次使用系统默认编码。新增检查防止管理端出现未指定编码的 Path 文本读写。
